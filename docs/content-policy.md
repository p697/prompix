# 内容来源、许可与下架政策

更新：2026-10-11。首版覆盖文本、图片、视频、网页；用来源配置、条目元数据和移除脚本实现基础处理，不建设复杂审核系统。

## 1. 原则

- 只收录白名单来源。
- 只全文展示许可允许的内容。
- 署名并链接原作者和原帖。
- 作者要求即下架。
- 来源透明：每条内容标注来源类型——作者原文、原创、由图片逆向、改写，或未知。

## 2. 来源接入候选与展示级别

优先选择可稳定取得内容的公开数据、允许采集的网页与原创内容；每个适配器启用前记录许可和获取方式。官方 Skill 已接入，社区 Skill 从明确作者的白名单逐步扩展；X API 用于发现和正文核验。下表是接入参考，不是已经全部上线的清单，竞品研究不自动加入采集白名单。

| 来源 | 获取方式 | 许可与条款 | 展示级别 |
|---|---|---|---|
| ClawHub | 公共 API，免鉴权 | Skill 统一 MIT-0；允许第三方目录，要求回链原页面、遵守限流、不暗示背书、不镜像被隐藏或拦截的内容 | 全文 |
| Anthropic 等官方 Skill 仓库 | GitHub API | 多为 Apache-2.0；docx、pdf、pptx、xlsx 四个 Skill 是专有许可 | 按文件夹判定；专有许可的只放链接 |
| YouMind OpenLab 的 Nano Banana Pro、GPT Image 2、GPT Image 1.5、Seedance 2 公开仓库 | 固定 commit 的 README | CC BY 4.0；记录作者、原帖和上游仓库 | 仅保留历史已发布条目和署名，不再采集新增 |
| prompts.chat | CSV、API | 提示词以 CC0 发布 | 全文 |
| 许可明确的文本、图片、视频、网页提示词仓库（如 EvoLink、freestylefly、jamez-bondos、PicoTrex、MeiGen） | GitHub | CC0、MIT、Apache、CC BY 等，以仓库的 LICENSE 文件为准 | 按条目和媒体的许可范围展示并署名；第三方媒体单独记录依据 |
| X 官方 API | 关键词检索热帖（按量付费） | 遵守 X 开发者条款和展示要求 | 署名并链接原帖；原帖删除后同步删除 |
| 没有许可证的仓库 | 不抓取正文 | 默认保留全部权利 | 不收录，或只放链接 |
| 禁止抓取的站点（如 PromptBase、FlowGPT） | 不抓取 | 条款明确禁止 | 不收录 |

## 3. 许可判定

- 用 SPDX 标识记录许可证。GitHub 仓库读取 LICENSE 文件；Skill 按所在文件夹判定，文件夹里的 LICENSE 优先于仓库根目录。
- README 徽章和 LICENSE 文件冲突时，以较严格的为准；无法判定的按"无许可证"处理。
- 可以全文展示：CC0、MIT、MIT-0、Apache-2.0、BSD、CC BY（必须署名并注明改动）。
- 不可以全文展示：
  - 没有许可证的内容；
  - CC BY-ND（禁止演绎，翻译也不行）；
  - CC BY-NC（v1 虽然不商业化，也不收录，避免以后受限）；
  - 专有许可。
- 翻译在版权上属于改编，只对允许演绎的内容做翻译后展示。

## 4. 署名与展示

- 详情页显示：作者名和主页、原帖链接、上游仓库及其许可证、来源类型。
- "关于"页说明：内容的许可、如何申请下架，以及与 OpenAI、Anthropic、Google、xAI 均无关联。

## 5. 不收录的内容

- 成人与性暗示内容、暴力血腥、仇恨与歧视内容。
- 仿冒知名 IP 角色或真人名人的内容，原帖是官方授权内容的除外。
- 越狱提示词、泄露的商业产品系统提示词。
- 含个人隐私信息的内容。
- 来源平台已隐藏、拦截或判定为恶意的 Skill。

## 6. 下架与认领

- 首版通过 GitHub issue 和 App 支持入口接收申请，不另建专用审核后台。
- App 详情的「反馈这条内容」进入 `https://prompix.dev/zh/report`（英文 `/report`），仅传公开条目 ID，再由用户选择进入 GitHub 表单。跳转前说明反馈公开可见且需要 GitHub 账号，不提交私人草稿或敏感证明。
- 负责人用移除脚本标记条目，发布静态移除清单并更新目录；客户端下次成功联网刷新时移除缓存内容，删除对应收藏快照。离线客户端无法即时同步。
- 内容工作目录记录处理原因与结果，争议由负责人跟进用户；不承诺无人值守的几小时自动处理。
- 后续需要公开处理记录时，不包含申请人的个人信息。

## 7. X 内容

- 新内容仍通过 X 官方 API 获取，不抓取 X 网页。TwitterAPI.io 可按[混合复查规程](x-hybrid-maintenance.md)核验已经取得的独立原帖：完整内容、媒体及署名一致才刷新可用性；缺失或变化交由官方确认，回复链继续整体官方核验。第三方响应单独留存，记录实际核验方，不进入官方发现目录，不用于新增发布，也不改写原始获取方式或展示依据。新内容搜索的第三方切换仍需通过[隔离实测](x-provider-pilot.md)的覆盖与来源检查。
- 遵守开发者条款和展示要求。
- 原帖被删除或作者把账号设为私密后，同步删除对应内容。

## 8. 来源台账

每条内容在仓库外的来源配置和 JSON 条目中记录：

- 来源 URL、作者、平台帖子 ID；
- 上游仓库，以及 commit 或版本；
- SPDX 许可证；
- 抓取时间、展示级别和处理历史。

App Store 审核要求出示授权依据时（5.2.2），以台账为准。

X 适配器允许完整作者、原帖、时间戳和附图/视频关联齐备的条目进入既有编辑与预览审核；通过后才可发布。来源标识 `X-API-Terms` 表示官方 API 展示条款，不冒充开放版权许可证。原帖全文保留，与摘出的指令及编辑翻译分开显示。每 12 小时尝试复查，官方维护预算默认每天 2 次 / 200 帖，配置硬上限 4 次 / 400 帖；混合模式另有受共享金额上限约束的第三方复查预算；超过 24 小时未核验的条目不进入新发布目录。明确删除、不可访问或被限制的帖子进入移除清单，客户端下次成功刷新时同步；API 故障不当作删除证明。当前用户可通过详情来源链接和 GitHub issue 提交问题。


允许直接采集作者维护的 `coreyhaines31/marketingskills` 的公开 `skills/` 一级目录，逐固定版本核验 MIT 许可并保存作者、来源和完整包身份。未审核包不会自动发布；不抓取配套付费站点，也不安装或运行采集到的 Skill。

2026-10-15 新增适配器检查白名单：通过 X 官方 API 的公开外链或 GitHub 官方搜索发现公开 GitHub Skill 仓库。允许检索仓库元数据和目录，不代表允许全文镜像。新发现包仅在最近的 LICENSE 是完整标准 MIT 授权、无冲突嵌套许可、固定 Git 版本及全部文件校验通过后进入编辑审核；实验、历史和测试目录不收录。没有许可证的仓库不下载包正文。媒体仅限同一许可包中明确引用并经过视觉审核的资源。详细限制见 [新来源发现](fresh-discovery.md)。
