# 0.12.2（45）：分类切换连续性

## 问题与范围

用户反馈发现页顶部「全部／文本／图片／视频／网页／Skills」切换时页面闪动。本轮仅修复筛选状态、内容交接与布局稳定性，不改 Tab Bar、详情导航或整体视觉方向。

旧版 0.12.1 模拟器录屏复现了：图片→视频→图片时，即使刚浏览过图片页，也会先清空成两块骨架，然后恢复卡片。代码链路为：KindPicker 修改筛选 → 新 query 的首帧与 store 不匹配 → FeedResults 隐藏旧卡片 → 异步 load 清空 store → 读取磁盘缓存 → 网络返回。清空期间瀑布流被卸载，恢复后重新测量列宽；全部页的创作者／用途区域移除和滚动复位又分别触发布局变化。

## 修改后的交接

- 分类选择同一轮更新 kind、Skills、用途及模型，清除不适用于新分类的旧筛选；同步选择对应 store 页面。重复点击当前分类不执行操作。
- 仅发现页启用最多六个查询的首屏内存快照，按最近使用淘汰。键包含完整规范化查询（语言、类型、模型、用途、排序等），不把其他分类内容暂留在新标题下。
- 五分钟内返回已访问分类：同步恢复其首屏及有效分页游标，不重复请求。切换仍回顶部，不保留无限长的分页列表。
- 超过五分钟：先显示该分类已有内容，后台重新取第一页；重新验证前禁止用旧游标分页。服务端报告快照过期也使对应内存页失效。下拉刷新仍强制请求。
- 从未加载过的分类：保持静态骨架，沿用磁盘缓存与网络路径，无人为最短等待时间。骨架与实际网格共用起点，空网格保持挂载以保存列宽。
- 发现页从稳定的滚动容器传入准确网格宽度，避免卡片重建时先用默认 180pt 分列再重新分配。图片增加 8MB 上限的 240px 缩略图缓存，后台解码；大图缓存淘汰后先显示缩略图，再补清晰图，明确清缓存时两级同时清除。缩略图不作为原图请求的成功结果。
- 快速切换取消前一个请求，UUID 所有权与任务取消检查继续阻止迟到结果写回。Retry-After 不因切分类而绕过。下架条目同时从活跃页和内存快照中移除。
- 一个完整 query 变化只复位一次滚动；锚点位于内容容器，不额外放置带栈间距的零高占位；结果区域不插入布局动画，分类选中线与原有滚动隐藏 Header 动效保持独立。加载期间内容高度至少覆盖视窗，避免短骨架使滚动区域突然缩短。

## 验证

本轮证据保存在仓库外 `/Volumes/Lucy-SSD/Prompix-Codex/Evidence/filter-transition-20261017/`。验证环境：Xcode 27.1 RC、iPhone Air / iOS 27.0 模拟器。

- FeedStoreTests：16 项通过，覆盖同步暖缓存、强制刷新、TTL、LRU、完整查询隔离、下架、迟到请求、限流和服务端快照过期。
- UI：分类循环切换与冷请求取消、Header 收起／反向展开／筛选复位通过；网络暂停时暖缓存不出现 `feedLoading`，不新增第一页请求。下拉刷新、离线恢复和提前分页回归通过。
- ImagePrefetchTests + LibraryTests：34 项通过，2 项需要独立视频网络夹具的测试跳过；本轮未修改视频播放逻辑。
- Debug 与 Release 构建成功。实际生产内容六分类切换录屏及冷／暖状态截图保存在上述证据目录，供逐帧对照。

首轮单测曾因测试使用不支持的 `zh-CN` 语言码失败，改为实际支持的 `zh-Hans` 后通过；没有放宽产品查询验证。

复现路径：打开发现 → 图片 → 视频 → 图片；再切回全部，向下阅读后向上滑出 Header，重新切分类。慢网络夹具通过 `hold-feed-refresh` 暂停响应，验证暖缓存直接显示、冷分类不显示旧卡片，以及离开冷分类后的旧请求不能覆盖当前内容。

已知边界：首次访问且没有磁盘缓存的分类仍需网络，会显示静态骨架；首次图片解码／下载仍可能出现局部图片占位。模拟器结果不等于真机帧率保证。本轮不安装用户手机。
