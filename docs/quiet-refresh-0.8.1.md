# 0.8.1（35）首页排序与刷新体验

首页移除独立“最新收录”模块，“全部内容”和分类、用途、模型筛选统一由新到旧。创作者和用途入口保留，搜索继续按相关性返回。排序依据是首次成功发布，翻译更新不会冒充新内容。

启动显示已有缓存并静默更新，不再出现“正在检查内容更新”等全局横幅。下拉刷新使用原生刷新动画，等待最新第一页返回才结束；保留原卡片至新数据成功替换，失败可重试。无缓存的首次加载仍显示局部加载反馈。首页顶栏位于滚动区域的安全区，不再遮挡系统刷新控件。

后台检查发现新发布时更新未翻页的首页；已翻页列表保持版本一致，用户下拉后重置为最新第一页。页面缓存区分排序，升级可复用上一版的 latest 缓存而不会套用旧精选顺序。

## 验证记录

本轮证据位于开发 SSD `Prompix-Codex/Evidence/QuietRefresh/`。最终 `acceptance-final.xcresult` 共 245 项通过、0 失败、2 项跳过：234 项原生模型测试和 11 项数据库 UI 场景通过；两项需要独立 HTTPS 媒体故障服务器的 AVPlayer 专项本轮未重跑，不能算作通过。九语界面检查通过。代码版本 `1ead941` 的 GitHub content 与 iOS CI 均通过。

UI 验证覆盖启动无全局横幅、慢网下拉后新增内容成为第一条、图片分类仍按最新排序、断网重启保留新列表、万条数据分页、全库搜索、真实线上最新条目与详情、旧版缓存迁移、离线收藏、草稿及语言切换。`owned-native-refresh.png` 是请求暂停时从模拟器实际截取的系统刷新动画；刷新前后和离线截图也保存在结果包中。

测试发现并修复了两层取消问题：懒加载子视图离屏时不能取消父视图持有的主动刷新；SwiftUI 刷新动作的生命周期变化也不能中断用户已经发起的请求。主动刷新独立持有有网络超时约束的任务，筛选变化仍由分页 store 取消旧查询。测试的慢响应在独立任务中释放，避免 XCTest 等待原生动画结束时堵住自己的模拟响应。
