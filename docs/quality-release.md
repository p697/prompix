### Build 4 的草稿失败保护

归档后的独立复核发现：原编辑器点击完成时会检查保存结果，但下滑关闭只在退出后尝试保存，写入失败会丢失本次尚未保存的文字。旧草稿本身未被覆盖。修复后，未持久化的修改阻止下滑退出；保存失败持续显示状态，并提供原生重试、继续编辑、复制并退出、明确放弃后退出的路径。主动退出后不再由延迟任务或生命周期回调重新保存已放弃的文字。

真实写入失败的模拟器测试进一步发现：全局错误弹窗会在手势操作之前关闭编辑器，导致仅禁用下滑仍不足以保护当前输入。草稿错误改为在编辑器内显示具体原因，缓冲区只初始化一次；全局收藏等错误入口保持不变。此项依据实际录屏发现，不把测试定位失败当作应用问题。

最大辅助字号的实际像素复查又发现，完整错误说明会挤掉正文可见区，虽然 XCTest 的元素存在／可点击检查通过，仍不接受该布局。说明区改为按内容自然高度显示、最多占当前可用高度的 45%；超出时原生滚动，保留正文编辑空间，不缩小辅助字体。原始 `Quality-Final-Draft-Largest-Text-4.xcresult` 保留为这个视觉缺陷的证据，不能把其中绿色断言当作视觉验收通过。

最终布局在 `Quality-Final-Draft-Largest-Text-4-Final.xcresult` 通过：53pt 正文字号下，固定复制栏上方保留约 326pt 编辑区，说明区可以滚动并实际点击重试与退出；原生退出确认取消后仍保留输入。实际截图复查通过，字号与测试草稿原样恢复。相同源文件在 `Quality-Final-Draft-Recovery-4-Scroll.xcresult` 再次通过标准字号的完整失败／恢复／复制退出路径，631 UTF-8 bytes 的复制文本逐字节一致，磁盘原始草稿精确恢复；记录分别为 `release-candidate/draft-recovery-largest-text-final-fixture-report.json`、`release-candidate/draft-recovery-scroll-fixture-report.json`。
