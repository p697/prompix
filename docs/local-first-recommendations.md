# 本地优先推荐与兴趣选择

2026-10-17，实施中。最终目标包含推荐系统、采集降本、分阶段历史补库及真机验收；这些部分分别验证，不能把候选生成或单个 PR 当成整体交付。

## 产品契约

首页及图片、视频、网页、文本、Skill、用途和创作者内的内容流使用推荐；搜索仍按相关性。首页保留「最新收录」供明确选择，移除首页与设置中的全库数量。每次冷启动、主动下拉刷新建立新的推荐会话；返回分类的暖缓存和从详情返回保持位置。浏览过程中的曝光、点击和收藏不能重排已经显示的卡片。

首次引导第四页选择兴趣：0.14.0 起按用户最新要求必须恰好选择三项后进入，不替用户勾选。设置内数量不限。设置中可修改兴趣、关闭行为学习、清除推荐偏好；收藏和草稿保留。「不感兴趣」立即退出推荐展示，并产生有限的相关主题负反馈。

初版参考依据（0.14.0 的强制三项为后续用户决策）：[Apple Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding) 建议快速、可跳过的引导；[X 推荐说明](https://help.x.com/en/rules-and-policies/recommendations) 将主动兴趣和媒体控制作为不同的用户控制。实现使用原生 SwiftUI 选择、滚动、导航及当前光谱色板，不复制竞品界面。

## 内容标签与画面尺度

`packages/schema/interests.json` 是服务端和 iOS 共用的稳定分类：人像与角色、时尚与穿搭、插画与艺术、产品与品牌、视频与电影感、网页与界面、写作与故事、学习与思考、生活与旅行、工作与效率、编程与开发、Skill与工作流。分类由已有编辑标签、内容类型映射，同一内容可以有多个主题；识别不了时保留空分类，不能伪装成模型理解了全部内容。类型推断不依赖译文标题。对现有837条快照的实测：771条至少命中一个主题，66条仍未分类（覆盖92.1%）；多主题会重复计数。尚未经过逐条主题正确率审读，后续可增加编辑器标签校正能力。

画面尺度独立于兴趣：`general`、`suggestive`、`explicit`、`unknown`。真实视觉审核查看完整传入图库或视频海报及抽帧，给出最严格的已见画面标记。人物性别、漂亮、体型、族裔或普通时尚不等于性感；不得推断年龄和身份。视频标记只代表已检查的抽样范围。旧的相关性 `match` 不能自动升级成 `general`，没有尺度证据的内容仍为 `unknown`。

「推荐画面更克制」默认开启，推荐流不展示已标记 `suggestive` 的内容，并降低未判定人像/时尚在候选中的集中度。选择人像兴趣不会关闭这个偏好。它不是对全部未审核画面的安全承诺。`explicit` 从发布候选及旧快照保留中排除，数据库发布入口也拒绝这类记录。新内容审核会附带尺度标记；旧库通过 `PROMPIX_VISUAL_CLASSIFY_PUBLISHED=1` 在原有共享视觉审核额度内补标；新内容和改动媒体优先，旧库只用剩余额度。当天未决/失败请求继续阻止重试，不得编造已检查的覆盖率。

## 端云职责

云端只接收内容筛选条件、语言、临时随机种子和签名游标，不接收兴趣、曝光 ID、行为、收藏或用户画像。推荐候选使用发布快照中稳定位置与带种子的哈希，少量最近120条的候选优先探索，其余覆盖完整筛选库存。种子在刷新时更换，不能用作固定设备 ID。旧版 curated/latest/discovery 保持原语义。

候选分页沿用视觉与纯文字双通道的混排、数量和响应字节上限。游标签名绑定会话种子、完整筛选、快照、两通道位置及期限；下架优先于任何历史快照。无 OFFSET 或随机重编号；每页仅加载各通道 limit+1 个卡片。种子哈希仍需扫描筛选后的轻量元数据，不能声称它是索引 O(1) 查询：一万条本地 SQL 与真实数据库延迟是独立验收项。

iOS 每批最多顺序获取3页、90张轻量卡片，再本地排序。主动选择兴趣、近期开启、收藏、使用及不感兴趣构成可解释的有界分数；行为权重按21天半衰期衰减。近期看过的内容降权，限制同一作者连续占位，每五个位置留一个探索位，并轮换探索位置以免与视觉混排绑定。排序保留云端视觉/文字槽位，不让行为偏好再次产生整屏纯文字。每批的排序只执行一次，分页追加不重排旧内容。

这是一版内容特征推荐，不是协同过滤或经过线上 A/B 证明的大模型推荐。有限候选、较小库存、稀疏分类和不完整尺度标记都限制效果；需要用真实内容实测重复率、兴趣命中、主题/作者多样性和前两屏视觉比例。

## 本地数据与失败语义

偏好文件独立于收藏、草稿与浏览缓存。只保留主动兴趣及最多3000项内容 ID、主题、类型、创作者 ID和有限事件时间/布尔信号；90天过期，排除系统备份，使用文件保护及原子写入。没有正文、搜索词、广告标识或联网接口。关闭学习后，主动兴趣和明确「不感兴趣」仍有效。重置推荐不删除收藏或草稿。

曝光仅在至少一半卡片可见、前台停留800ms后记录，预取、构造卡片不计曝光；iOS17缺少可见性回调时只学习显式操作。不重复累加同一内容点击来抬高权重。损坏文件保留并停止覆盖，明确重置才能替换。服务失败保留原页面与离线缓存；磁盘游标必须重新验证，分类内存快照同时保存其私有会话查询，避免跨种子翻页。

## 验收关口

- SQL：种子轮换、过滤、大小变化、完整遍历、删除、并发发布、游标签名/过期与一万条性能。
- 原生：兴趣与行为效果、探索和作者多样性、重复降权、文件损坏/重置、持久化/关闭学习、池大小、分类缓存和分页会话。
- 视觉审核：实际图片与标记绑定，旧证据保持 unknown，explicit不能通过保留旧快照重现；真实内容补标需单独记录。
- 模拟器：兴趣选择/跳过/设置、默认推荐、刷新轮换、旧卡片稳定、分页、离线、辅助字号和减少动态效果。
- 真实接口与真机：上线身份、延迟、回滚记录、签名及个人数据保全、安装到 iPhone17 Pro；未完成前不宣布交付。

本地/CI/生产证据保存在仓库外的 recommendation-delivery 检查点。历史补库和低成本权威复查继续沿用 X 检查点、共享预算及已有合规 job，不因推荐实施而重启付费任务。

## 2026-10-17 真实内容上的本机排序对照

在当前836条线上发布快照中读取22组独立种子候选：首页12组，图片、视频、网页、文本、Skill各2组，每组沿用客户端最多3页／90条的限制。共62次自有HTTPS读取，没有付费X请求。冻结候选、临时测试画像和结果均保存在仓库外。iOS模拟器直接运行产品的 `LocalRecommendations`，覆盖12个单项兴趣和3个组合兴趣，共330组画像／会话对照；没有把评分算法复制到另一个语言里测试。

以下是首页前30条的平均标签匹配数。学习列使用候选池之外的12条同主题内容模拟此前点击，未主动选择兴趣：

| 本机兴趣 | 无偏好 | 仅此前点击学习 | 主动选择兴趣 |
|---|---:|---:|---:|
| 人像＋时尚＋插画 | 14.3 | 19.5 | 24.7 |
| 产品＋网页＋视频 | 14.1 | 19.8 | 23.8 |

| 人像 | 3.8 | 11.3 | 20.8 |
| 网页 | 0.4 | 1.4 | 1.6 |

12次首页会话逐次记录前30条曝光后，本地降权在这批固定候选中选择了360条不重复内容；这是该样本结果，不是“每次刷新保证全部新内容”。分类的第二次刷新：图片、视频、Skill没有重复，文本1条重复；网页第二次仍为同样7条，因为库存只有7条。排序不会制造不存在的内容，网页供给仍需补齐。

所有画像都保留视觉／文字槽位、完整候选集合和确定性顺序；已标记suggestive的内容被默认画面偏好过滤。前30条平均有约25位不同创作者。关闭行为学习后，使用同一候选的排序恢复到无行为画像的基线。测试的改善门槛按当前候选池和视觉槽位可供给的匹配量计算，避免把供给不足误报成排序失败。

Release优化的模拟器回放中，每个最多90条候选池的排序中位约3.3ms、P95约5.0ms；这不是物理手机耗时，也不是网络、解码和整页渲染耗时。兴趣匹配取决于现有标签，不能代替逐条人工相关性审读、画面补标或线上留存/A-B结果。测试画像是合成的，本机真实用户的点击和兴趣没有上传。

复验方法：创建仓库外的目录，运行 `node --import tsx scripts/capture-recommendation-pools.ts --output /absolute/external/directory/pools.json`。脚本拒绝仓库内路径及覆盖已有文件，遇发布快照切换或HTTP错误停止，并保留未完成证据。通过测试运行配置传入 `PROMPIX_RECOMMENDATION_POOLS` 和仓库外的 `PROMPIX_RECOMMENDATION_REPORT`，运行 `LocalRecommendationTests/testPublishedCandidatePoolsMeasureInterestLiftAndExposureSuppression`。没有外部数据时CI明确跳过这项真实内容验收；确定性合成回归仍持续运行。

## 2026-10-19 收尾与下一轮验证范围

本轮没有改推荐权重。生产generation35的2549条快照（另外的合格补库待发布单列）实际分布：
图片1653、视频454、文本435、网页7。按当前共享规则重算，2513条至少命中一个兴趣（98.6%），36条未分类。
这是规则覆盖率，不是标签准确率。主题可重叠：人像1276、时尚558、生活762、插画614；库存明显偏向人像与视觉。
尺度为general1821、suggestive314、unknown414；unknown不能当作已安全审核，尤其不能以标题猜测尺度。
证据在仓库外campaign的`closeout-inventory-audit.json`，没有再次调用付费来源或模型。

当前已经具备：12类可多选兴趣、独立尺度偏好、曝光/点击/收藏/使用/不感兴趣学习、近期曝光降权、作者分散、
探索位、视觉槽位、会话刷新、签名分页、关闭学习和清除偏好。云端不收用户画像；本机最多重排90张候选，
因此小众兴趣不一定能召回足够内容。没有embedding召回、协同过滤、跨设备画像或线上效果A/B证明。

下一轮讨论建议按以下顺序，不以继续扩到10000作为前置条件：

1. 固定线上快照，分主题与尺度分层抽样，检查真实标签准确度、漏标、多义词误命中与创作者集中。
2. 用真实库重跑产品本机排序：冷启动、单兴趣/组合兴趣、点击学习、负反馈、多次刷新及分类页，记录前30条兴趣相关性、
   重复率、作者/主题多样性、前两屏视觉比例。既有836条/330组对照是历史证据，不能冒充本轮2549条的复验。
3. 优先讨论是否增加可校正的标签维度：主体/主题、视觉风格、用途、工具/模型。尺度保持独立，并保存来源、版本与可信度。
   不必在onboarding一次展示全部细标签，也不把人物性别、漂亮或体型等同于性感。
4. 先对比当前基线与小范围候选/排序调整，再决定是否需要本地向量或更大候选池。隐私边界若改变，须作为显式产品决策。
5. 网页类只有7条，排序不能消除供给不足；少量定向补齐应与全量扩库区分。

本轮目标是建立可复现的产品验收，不把离线标签匹配提升当作真实留存提升。产品阈值与体验优先级待讨论确认。
