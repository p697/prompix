## 范围与发布关口

- PostgreSQL 保存内容身份、不可变修订、译文、发布快照、作者、来源、审核/输入任务记录与下架状态；R2 继续保存媒体和来源原始文件。
- v3 列表按游标返回有界卡片，不携带正文、完整 Skill 文件清单或原帖上下文。详情按 ID、修订和语言读取；缺译文保留原文。
- Feed 游标绑定发布快照与筛选条件；同一次翻页不因新版本插入而漂移。下架立即覆盖所有历史快照的可见性，不能靠旧游标恢复。
- 收藏、草稿与浏览缓存分开。分页未返回的条目不代表下架；客户端只根据独立变更记录移除内容。原文/译文草稿与稳定内容 ID 保持兼容。
- 已发布修订始终独立于准备中的修订。导入与激活可重试；数据库失败不改变旧活动版本。单一写入入口控制发布，公开 API 使用最小只读权限。
- input 层保留来源白名单、指纹审核、媒体核验、预算预留与未决请求；数据库迁移不触发重新付费采集。定时更新必须有自然运行证据和可观测的失败状态。
- 保留 v1/v2 兼容导出及下架更新，不提高旧客户端的 1,000 条/10 MB 限制，不冒充旧客户端拥有完整新库。

本阶段交付内容数据库、分页/详情/搜索/作者 API、原生按需加载、输入管线衔接及运维验证。账户、订阅和团队协作不属于这次内容服务升级的已实现功能。

## 数据与查询

内容 ID 沿用现有值。修订绑定原文、来源、媒体及所有已批准译文的完整指纹，旧修订不覆盖；原文指纹继续用于个人收藏和译文一致性校验。发布快照保留现有编辑顺序并按 position + ID 翻页，避免迁移时把精选与模态交错改成未经确认的排序。

数据库使用独立 schema；公开读角色没有 DDL/DML、草稿、任务凭据或预算写权限。输入参数受类型、长度、页大小和游标校验；所有查询参数化。每次查询/响应均有时间、行数和字节预算。正文和翻译只出现在详情接口。

分页端点同时支持类型、Skill、作者、标签、模型与关键词。中日韩等无空格查询必须实测，不能以英文全文检索通过代替多语搜索验收。作者数量来自全库聚合，不是已加载页面的局部数量。

## 一万条托管数据库实测（2026-10-15）

在实际 Supabase Micro/PostgreSQL 17 上，用事务内隔离 schema 生成一万条自有合成内容、三万份译文和五百位作者；使用与服务相同的 SQL、只读角色及 RLS。所有建表、数据和临时角色授权在结束时回滚，生产发布仍为 generation 1；回查无测试 schema，管理员原有角色管理授权的继承与 SET 权限均未扩张。生成器为 `scripts/prepare-feed-benchmark.ts`，只输出仓库外 SQL，执行是独立步骤。

测试找到了仅靠小数据测试未发现的问题：广泛匹配的搜索误估结果数，对 content 重复顺序扫描约五千万行，三轮耗时 9.11–9.29 秒。修复先确定搜索候选的可见性，再做相关度排序，最后只取当前页卡片和译文；普通无关键词分页保持索引过滤。没有关闭 RLS 或更改下架规则。实现依据 [PostgreSQL CTE materialization](https://www.postgresql.org/docs/17/queries-with.html#QUERIES-WITH-CTE-MATERIALIZATION)。

| 查询 | 最小 | 最大 |
|---|---:|---:|
| 首屏 30 条 | 4.48 | 4.62 |
| 第 9,001 条后的游标页 | 4.45 | 4.56 |

## 有界线上并发与限流验证（2026-10-15）

部署版本 `10b1a9cc-919a-4811-b74c-e8d6b189c508` 在正式域名以八路并发完成 40 次分页、搜索、作者和状态读取，全部 200；继续对无效参数发出 180 次 GET（验证在建库连接前拒绝），得到 120 次 400、60 次 429。429 的 `Retry-After: 60`、无缓存和安全响应头通过检查。该轮保持 HTTPS 连接，220 次入口均为 NRT，无传输失败，约 45 秒完成。

40 次正常读取的本机中位 386 ms、P95 1,051 ms、最大 7,855 ms；长尾仍需连接与服务端耗时分解，不能当作已满足延迟目标。此前使用默认 fetch 连接策略的两次探测记录了 TLS 建连中断；另一次成功读取后未观察到 429，未冒充限流通过。上述失败均保留在外部证据中。`scripts/check-feed-resilience.ts` 固定请求规模并输出失败统计，支持独立 `--reads-only` 恢复检查；不要与同一 IP 的其他配额探测同时运行。这不是万人并发或持续吞吐能力测试。

限流窗口结束后，八路并发的 40 次真实读取再次全部 200，无传输失败。恢复轮中位 347 ms、P95 1,222 ms、最大 1,241 ms；最慢请求 TLS 建连 739 ms、Worker/DB 45 ms。它证明该轮主要耗时在连接与网络，不足以回溯此前未记录细分耗时的 7.9 秒请求。客户端仍需明确的加载、取消、重试和离线回退。
