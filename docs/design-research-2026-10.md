# 2026-10：发现、创作者与国际化设计依据

调研日期：2026-10-12。本文区分官方事实、实际截图观察和 Prompix 的实施建议；建议不是已完成功能或获奖承诺。查看了当前原生 `DiscoveryView`、`CollectionsView`、`PromptDetail` 和 `Theme`，并在浏览器实际查看下列 App Store 的 iPhone 截图。没有安装或实际操作这些第三方 App，因此不把静态图推断成经过测试的动效、性能或完整流程。

## 当前体验的主要缺口

当前首页直接从类型、用途、模型筛选进入单一瀑布流；用户只能筛选已有目标，缺少认识创作者、按任务探索、发现新技能的入口。详情的作者信息出现在完整 Prompt 之后，难以建立「喜欢一个作品 → 看同一作者更多作品」的路径。收藏只有一个平面列表。已有原生导航、双列内容、图片与视频预览、系统分享和本地草稿应保留并完善。

丰富度应来自可用内容之间的关系：作品、作者、任务、技能、来源。新增按钮、巨幅标语、装饰性英文和虚构社区数字不会补足这个缺口。

## 本轮实施方向

### 1. 首页：让人既能逛，也能迅速缩小范围

由上到下：

1. 原生紧凑导航栏：Prompix、搜索、设置。品牌只在这一处出现。
2. 类型选择：全部、文本、图片、视频、网页、Skill。类型名称本地化；横向滚动，不压成难点的小字。
3. 「创作者」横向列表：真实头像、显示名；点开完整主页。提供「查看全部」。含 44 pt 可点击标题行在内，常规字级总高度控制在约 130 pt，不做大幅人物横幅。
4. 「按用途探索」横向合集：用真实内容的封面组合、具体任务名称和实际收录数量。常规字级约 170 pt 总高度，一屏露出下一张以表达可横滑。
5. 完整 Prompt/Skill 内容流：两列，真实作品优先，文字和技能卡有各自的内容表达。保留搜索、筛选与收藏。

首页在常规 iPhone、默认字级下应露出第一排内容流的一部分；顶部合集自身也必须是具体可点开的真实内容。若实际布局把内容推到整屏以下，应减小合集高度或只保留一个发现模块，不再加横幅。

选择某一类型、用途或模型后，优先显示结果，收起不相关的发现模块。筛选条件可见，有结果数量和清除入口；不要让筛选后仍要滚过一屏推荐。返回时保留原列表位置，刷新不得在阅读过程中重新排序正在看的卡片。

首页只使用可兑现的名称，例如「创作者」「按用途探索」「全部内容」。没有真实个性化或时间规则时，不使用「为你推荐」「今日精选」；不恢复 Daily Finds 一类装饰文案。

### 2. 创作者：从署名变为完整发现路径

主页结构：原生返回栏 → 64 pt 头像、姓名、账号与平台 → 有依据的原始简介 → 实际收录数量和「在 X 查看」/「在 GitHub 查看」 → 内容类型筛选 → 该作者的作品流。

- 首页头像、卡片作者行、详情标题附近的署名指向同一主页。
- 作者身份以平台与稳定账号 ID 绑定；缺少 ID 时使用规范化账号或来源 URL。不能按显示名合并，不能将 YouMind 等聚合者当成原作者。
- 头像失败时显示稳定的首字母或系统占位，不阻塞内容；缓存后的作者页离线可读。
- 只显示已采集并验证的字段。不生成作者履历，不编造认证、粉丝、热门程度或社交关系。
- 如果加入「关注」，定义为本机保存作者并提供「已关注」列表；明确其作用，不暗示已经关注了外部 X 账号。若没有内容回访入口，本轮不放一个无后续作用的关注按钮。
- 外部账号链接必须来自经过校验的源数据。打开外部页面用系统浏览器或原生链接，保留返回路径。

### 3. 卡片与详情：预览、理解、使用

卡片保持一个主点击区域和独立收藏动作。常规卡片是作品 → 2–3 行具体标题 → 作者/类型；不堆满模型、标签、来源、日期和计数。视频显示播放标识，播放由用户主动开始。网页显示真实预览，文本呈现短用途和输入线索，Skill 呈现能力、适用工具与来源。

详情把作者入口移到标题附近。保留主要的「复制」和「编辑后使用」动作；长正文可渐进展开，但复制必须复制完整选定版本，不能复制截断预览。来源、许可和报告入口保留在可找到的区域。不会执行 Skill 中的命令；查看、复制、下载/打开来源和安装到外部工具是不同能力，应给出准确名称。

内容语言用一个明确的菜单或「原文 / 翻译」控制：显示当前语言、允许回到原文；缺少翻译时明确显示原文。复制、编辑、分享必须使用用户当前选择的版本。切换语言不得覆盖另一版本的本地草稿。

### 4. 原生组件和视觉尺度

| 项目 | 实施约束 |
|---|---|
| 导航 | `NavigationStack`、系统返回手势、原生 `TabView`、`Menu`、Sheet、分享面板；根页面不要套多层自制导航条。 |
| 图标 | 使用语义明确、同一字重的 SF Symbols。发现、专题/探索、收藏以 `square.grid.2x2`、`rectangle.stack`、`bookmark` 为候选；最终用实机比例的模拟器截图比较，避免自绘图标线宽不一致。 |
| 字体 | 系统语义字级；标题有明确层级，内容正文可读，作者和辅助信息仍遵守可访问性字级。品牌 serif 不扩散到每个模块标题。 |
| 间距 | 页面水平 16–20 pt，双列间距约 12 pt，主要模块间距 24–28 pt。圆角形成小量一致尺度，不让所有元素都成为厚重圆角容器。 |
| 颜色 | 系统主/次背景和语义文字色，单一低饱和强调色。图片承担大部分色彩；不要给每个类别一个艳色背景。 |
| 反馈 | 收藏立即改变状态并有轻触感；复制有可读完成反馈；错误就地提供重试。动画服务于导航和状态变化，Reduce Motion 下不依赖缩放/视差表达状态。 |
| 适配 | Dynamic Type 或 VoiceOver 下使用单列有序内容和可读的作者/合集行；控件至少 44 pt 点击区域。iPad 限制阅读宽度，避免把手机两列拉伸成巨卡。 |

收藏夹是后续值得加入的组织功能，但必须有完整的创建、重命名、增删条目、空状态和持久化闭环。优先完成作者、技能和国际化，不把一个不完整的「画板」入口放进交付版。

## 国际化范围与内容策略

建议本轮支持 **9 个 locale：`en`、`zh-Hans`、`zh-Hant`、`ja`、`ko`、`es`、`pt-BR`、`fr`、`de`**，即英文、简繁中文、日文、韩文、西班牙文、巴西葡文、法文和德文。

这是产品优先级判断，不是市场份额结论。中英是用户明确要求；[GitHub 2025 Octoverse](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)显示生成式 AI 开源贡献来自多地区，包括日本、韩国、德国、巴西、西班牙和法国，提供方向性依据；它不能代表移动 Prompt 用户的语言比例。[Cosmos 官方帮助](https://help.cosmos.so/en/articles/17508467-cosmos-basics)也记录了跨端多语言支持，说明同类发现产品已经把本地化当作完整体验的一部分。其 App Store 的语言元数据与帮助文档不一致，所以不以商店语言栏推断真实支持范围。

界面语言和 Prompt 原文语言是两个概念。所有导航、操作、空状态、错误、数量、辅助功能文案都应本地化；作者名、账号、模型名、产品名通常保留。标题、摘要、使用说明与正文可以有审核后的翻译，原文永久保留。

翻译采集链路应使用外部缓存和内容哈希，按新增/变更条目增量处理。请求可批量执行，但每条结果需绑定源版本；失败或待审核的语言不冒充已完成。变量占位符、JSON 字段、代码块、命令、路径、URL 和模型参数必须保留。Skill 的说明可以翻译，机器可执行配置和标识不能随意翻译。界面和内容术语维护统一词表。

默认按系统或 App 语言展示可用译文，缺失时回退原文并标示。搜索同时覆盖本地化标题、原文、作者、模型、来源和用途；切换语言不让收藏丢失。发布前至少抽检各语言真实内容，不能仅用翻译条数证明质量。

## 验收演示与可测关口

以下为交付关口，不能在未执行时标成完成。

| 场景 | 必须展示的结果 |
|---|---|
| 首次打开与闲逛 | 有真实预览、可识别的作者和任务入口；无测试文案、空口号、虚构数字；从首页不超过两次点击进入作者或具体任务内容。 |
| 作者闭环 | 首页作者 → 主页 → 作品 → 返回，作者数量与作品一致；来源跳转正确；同名不同账号不误合并。 |
| 定向寻找 | 选择类型/模型、搜索本地化词或作者；筛选状态清楚，空结果有恢复路径；返回原滚动位置。 |
| 使用闭环 | 查看预览 → 切换原文/译文 → 修改 → 复制 → 重开草稿；复制内容、当前语言和草稿一致，变量未损坏。 |
| Skill 闭环 | 可发现、看适用工具和说明、保留源地址、复制完整内容；没有伪装成可用的安装或执行按钮。 |
| 收藏与更新 | 收藏 Prompt/Skill，重启和离线后仍在；新内容更新不改变作者身份或丢失草稿；头像失败有稳定占位。 |
| 原生质量 | 小屏和标准屏、浅深色、最大辅助字级、Reduce Motion、VoiceOver 顺序均检查；原生返回、Sheet 关闭和键盘遮挡无阻塞。 |
| 多语言 | 9 个 locale 全量 key 检查；中英日和德文长文案实际截图；所有支持语言跑导航、空状态、翻译回退与复制检查。 |
| 稳定性 | 连续浏览至少 100 个实际可见条目；作者/类型切换重复 20 次；无崩溃、明显跳动、持续增长的视图状态或主线程阻塞。首次显示与内存用量按相同模拟器条件记录，不将模拟器指标冒充真机表现。 |
| 最终演示 | 一段真实模拟器录屏覆盖首页 → 作者 → 作品 → 译文/原文 → 复制/编辑 → Skill → 收藏 → 搜索，附代表性截图。不得用静态设计稿代替已实现流程。 |

本轮无需向用户手机安装；模拟器验收演示与质量证据准备完成后再交付。
