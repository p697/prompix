# 0.10.1（41）：首页加载与封面去重

创作者骨架和实际卡片共用 `CreatorRailCard`：104 点基础宽度（随字号缩放）、80 点预览高度、7 点文字间距与同一行 caption。无作品预览的作者仍保留完整预览区域，头像不再让横栏变矮。请求失败在同一空间内提供重试；缓存内容在后台刷新时继续显示。

“按用途探索”从第一帧呈现固定用途入口，预留同尺寸封面与计数，不再等 metadata 返回后插入整块卡片。封面由 140 点缩至 116 点，文字间距从 10 点缩至 8 点；标题保持一行，完整名称仍由辅助功能读取、专题页展示。辅助字号／VoiceOver 保留原有简明用途入口。全部内容骨架复用现有 LoadingSurface，并去掉额外加载提示行，避免加载完成后顶边上移。图片下载继续在卡片已有的比例框内完成。

用途封面避开首页最新流前 8 项、前 12 位创作者的代表作，以及本行已经使用的其他用途封面。同时比较内容 ID 和图片来源，避免不同记录使用同一图片。候选仅来自现有专题封面和最新流首 30 项中匹配该用途的条目；已下架内容排除。优先使用图片／网页预览，避免把文本Skill拼进图片组合；纯文本用途只保留一张可读封面。不足时保留一张封面，无合适候选时显示用途说明和主题符号。它不改变“全部内容”的最新排序、数量或分页，不额外请求整库，也不保证用户继续滚动后永远看不到同一作品。

首页最新请求由发现页持有，不再依赖瀑布流进入 LazyVStack 可见区域，避免等待候选时形成加载依赖。其他列表沿用自己的请求生命周期。

验证证据保存在开发 SSD 的 `Prompix-Codex/Evidence/HomeLoading/`，截图和第三方作品不进入 Git。测试通过明确的 Debug 模拟器专用开关暂停三个独立请求，比较创作者、用途和全部内容的垂直位置；生产 Release 不包含这些故障注入。

- 原生模型套件执行247项：244通过、3项环境限定跳过、0失败；其中新增封面选择测试覆盖内容ID／图片重复、候选不足、选择上限和原始候选顺序保留。
- `ui-3.xcresult`：三条完整UI流程通过。独立接口分批完成、失败→原位重试、离线缓存重启时，创作者／用途／内容筛选按钮垂直位置差均不超过1点；最新排序、无启动横幅、主动下拉刷新和新增内容也通过。
- 首次编译缺少闭合括号以及首轮UI父级测试标识覆盖子按钮定位均已修正；失败日志保留。首轮Xcode诊断收集停滞，终止后关闭自动诊断收集重跑成功。
- 本机只安装了iOS27.1 Duo运行时，使用独立模拟器的单面窄屏测试，不能将它称为iPhone17 Pro专用模拟器或所有系统版本验证。

线上截图复查发现备用候选会把文本Skill拼入人像封面，已改为视觉候选优先、纯文本只显示单张。线上流程的返回按钮在Duo侧边工具栏而非navigation bar，已按实际辅助功能标识适配测试；这两处修正后重新验证。
