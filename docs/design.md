# 设计方向与首版交互要求

更新：2026-10-11。**状态：用户已确认「轻盈发现」：小红书的浏览结构 + Cosmos 的克制与品位。已进入原生 iOS 实现。**

## 1. 核心原则

像逛手机淘宝和小红书一样发现有意思的 Prompt：用户即使没有任务，也愿意多看几屏。兼顾设计感、品位、内容密度与原生操作，不把首屏做成工具目录或大段指令列表。

已从三个方向中选定「轻盈发现」。采用明亮、安静的系统背景与墨色文字，内容承担颜色；双列错落浏览，12pt 卡片圆角、12pt 列间距、16–22pt 页面边距。正文使用系统字体，字标和部分封面使用衬线字体。发现／专题／收藏使用原生 TabView；原生导航、搜索、分享、编辑与播放器优先。支持系统暗色模式与动态字体，大字号切为单列。首版视频点击播放，不在列表自动播放。动效克制，不做装饰性视差。旧暗色加亮绿不沿用。

## 2. 核心页面

| 页面 | 首版内容 |
|---|---|
| 发现 | 混合内容流、全部／文本／图片／视频／网页频道、用途入口、精选专题、搜索入口 |
| 搜索与浏览 | 关键词、内容类型、模型和用途筛选；结果继续使用统一卡片体系 |
| 详情 | 适配四类预览、用途与示例、完整 Prompt、素材要求、作者来源、相关内容 |
| 使用 | 简单编辑、复制、系统分享、适用工具；未经验证不标自动预填 |
| 收藏 | 本地保存、类型筛选、离线文本和缩略图、再次复制 |
| 设置与支持 | 缓存管理、播放偏好、隐私、来源说明、联系与移除入口 |

不强制六个独立导航项或旧版十屏结构。导航层级与卡片比例在设计确认时决定；低频设置可用入口承载。

## 3. 四类卡片

- **文本**：短标题、用途、示例回答或对话；封面可辅助氛围，不能掩盖实际用途。趣味与实用内容都要有吸引力。
- **图片**：效果图优先，清楚区分输入参考图和输出；详情支持缩放与 1–8 张分页图集，仅展示编辑核对过、与正文对应的预览。
- **视频**：封面、时长、播放状态；列表不自动播放；用户在详情明确点击后观看，进入后台停止播放。
- **网页**：截图／演示视频、作品用途；详情可打开演示，说明需要的工具或电脑环境。

类型、模型和来源各自独立。网页的录屏不被误标成视频 Prompt。封面或示例为编辑制作时如实标明；不填虚构收藏数、点赞数、评分或验证标签。

## 4. 浏览节奏

- 默认混合发现，不要求先选模型；分类解决“我想看什么”，精选专题制造继续逛的理由。
- 文本、图片、视频、网页卡片在同一视觉体系中协调呈现，避免文本沦为不显眼的占位。
- 控制相邻重复、同作者刷屏和类型扎堆；首版使用编辑顺序与简单规则。
- 跨类型专题可以串起一个愿望，例如生日惊喜、旅行记录、个人品牌。
- 返回保持滚动位置，收藏和复制有清晰反馈，加载／空／错误状态符合最终视觉方向。

## 5. 原生与可访问性

- 采用原生导航、返回手势、图片缩放、视频播放、输入和系统分享。主界面使用 SwiftUI；网页 Prompt 的原创作品在隔离的 WebKit 预览中打开，历史 HTML 稿仍仅供设计参考。
- 触控区域至少 44pt，支持动态字体与 VoiceOver，文本对比度按可访问性要求检查。
- 尊重减少动态效果和低数据模式；离屏与进入后台停止列表视频。
- 长 Prompt 可展开、选择、编辑和复制，不让底部操作遮挡正文。
- 收藏的离线能力明确到文本和缩略图；在线网页、未缓存视频有真实不可用状态。

## 6. 旧稿使用说明

[`design/v2/`](../design/v2/index.html) 保留历史静态稿。可参考搜索、分类、详情、收藏的布局思路，但其中 Skill、以图搜、同步入口、个性化频道、数值和颜色均不代表当前承诺。新版需补齐文本与网页的完整体验，不以旧稿十屏逐屏实现作为验收目标。

## 7. 自适应浏览改进

发现页将用途与模型筛选合并为一行，保留横向滚动和系统菜单。专题封面使用实际条目的三幅预览，选择多种内容类型；专题数量和列表来自同一筛选结果。相关内容优先匹配具体标签，再按类型和模型排序，避免只因通用标签相同而反复推荐。

最大辅助字号下，主操作使用简短可见文案并保留完整无障碍名称；按钮随字体增长，编辑区保留系统字号。详情的模型信息可换为纵向排列。发现页分类、用途与收藏按钮的实际触控区域至少 44pt，图片双击缩放尊重减少动态效果。
