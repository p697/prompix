# 新来源发现、最新收录与采集监控

状态：2026-10-15，服务端和监控已部署，0.8.0（34）已安装用户 iPhone Air。生产运行与最终交付的原始记录保存在下述仓库外证据目录。

## 产品约束

X 是优先发现渠道；重点是图片、视频、写作、网页及创意型 Skill。减少 Expo、Supabase 等开发配置内容对首页和审核预算的占用。每日新增 50–100 条是质量达标后的目标，100 条是硬上限，不能为了凑数批准内容。公开 Agent Skills 格式以 SKILL.md 为入口，完整包可包含参考文件、脚本和资源；有格式兼容不代表不依赖特定服务或能在所有工具运行。手机负责浏览、保存和交接，不运行第三方脚本。

## 输入与审核

- 保留现有来源维护，同时轮换 X 的图片、视频、文字、网页、创意 Skill 查询，增加视觉方向的搜索词。X 每日请求及帖子预留总额不提高；按 UTC 四个六小时时段累计释放 25%、50%、75%、100%，未使用额度可在后续时段使用。回复补抓最多约占六分之一，其余用于新发现。
- X 的结构化 expanded/unwound 链接进入 GitHub 仓库发现队列，即使帖子本身没有可复制的 Prompt 正文也保留线索。公开 GitHub API 是新增适配器的检查白名单；能被发现不等于可以发布。
- 每六小时最多一次轮换 GitHub 创意类仓库搜索，每轮最多检查三个仓库、每仓库五个待核验包。优先 X 及创意方向；有足够线索时分配两个 X 仓库及一个搜索仓库，优先从未检查或最久未检查的线索，避免固定热门仓库占满预算。队列与成功检查结果持久化。失败包后续可重试，不被永久标为完成。
- 仓库必须公开、未归档、未禁用，固定到当前默认分支的 Git commit。仅取正式包目录，过滤 evidence、tests、fixtures、eval、archive、experimental 等目录。最近的 LICENSE 优先，许可不明、修改过的 MIT 授权或不支持的嵌套许可证暂缓。
- 包最多 200 个文件、单文件 2 MB、合计 5 MB。拒绝截断目录树、重复路径、路径穿越、符号链接和子模块；逐文件下载并核对固定 Git blob，外部保存 SHA-256 清单。校验文件完整性不等于执行测试或安全审计。
- 正文完整性、可用性、创作质量及前置依赖仍进入既有编辑审核。新增审核容量按 X 50%、创意 30%、维护 10%、技术 10% 轮转，空队列让出额度。发布前还有视觉审核、翻译审核、去重和下架检查。
- 封面仅采用同一许可包内正文明确引用的栅格图片，再经过现有镜像和视觉审核。没有合格图片时保留诚实的文字封面，不伪造运行效果。

## 首次发布时间和新增数量

数据库记录 first_published_at，仅在成功激活时赋值；暂存、补译、编辑、回滚和删除均不重置。历史数据按最早保留的发布记录回填，该日期不代表原帖的互联网发表时间。每个 release 在激活时固定 latest_position，索引支持 `sort=latest` 的快照游标分页；默认精选顺序继续兼容旧客户端。用途探索的封面也优先近期收录。

媒体及质量门禁通过后、翻译前，按同一 UTC 日的持久化首次发布记录，选择当前时段允许的新增；未选条目仍保留在候选和审核缓存中。数据库激活在 state 行锁内再次检查每日 100 条硬上限，防止并发、重试、回滚补回额度。首次迁入历史库不消耗新增额度。备份 v2 额外保存所有首次发布身份，包括已不在当前版本的条目，恢复演练验证顺序和额度不丢失。

首页首先显示“最新收录”横栏，点击“查看全部”打开独立最新流；原有精选、创作者、用途探索保留。Skill 有真实来源图片时使用图片卡面，文字说明保留标题、完整说明与依赖提示。界面覆盖九种语言。

## 失败恢复与邮件监控

数据库仅连接建立阶段最多四次尝试，间隔 1/3/8 秒；不盲目重放结果不确定的提交。X 明确的网络故障、HTTP 429/5xx 可在现有总预算内重新预留请求后重试，最多三个失败尝试；每次尝试都消耗预留额度，保留原游标并遵守 Retry-After。中断的未决预留、身份错误和不可重试错误保持阻断，避免不受控支出。

Cloudflare Worker + 一个采集管线 Durable Object 独立于 Mac 运行。采集报告开始/结束事件通过 Bearer secret 上报，只发送运行身份、时间、成功/失败、是否发布和降级布尔值，不传原始异常或凭据。监控检测运行失败、运行超过两小时、八小时无成功、二十六小时无成功发布、二十六小时无新增内容，以及连续两次来源/审核降级。故障合并为一个事件，成功解除后发送恢复邮件。

邮件 outbox 持久化，失败按 5/10/20/40/60 分钟退避，闹钟在外部邮件 I/O 前重新设置；普通重复心跳不会重复通知。邮件提供方与数据库之间无法建立分布式事务，进程恰好在邮件接受后、确认持久化前崩溃时仍可能重发同一 Message-ID，不能承诺绝对只发一次。

收件地址和密钥仅位于 `~/.config/prompix/alerts-worker.json`、`alerts.env` 和 Worker secrets，代码库不包含真实值。收件邮箱已验证，域名既有邮件路由已启用。验收独立 Worker 已完成认证拒绝、事件大小限制、故障/恢复通知的真实 API 测试，邮件 binding 已接受两封带“验收测试”前缀的通知；这不代替用户确认收件箱到达。测试 Worker 在测试后删除。正式监控部署后必须收到采集心跳才算完成接入。

## 运维入口与边界

- 定时任务由本机 launchd 在 02/08/14/20 点启动；Mac、外接内容盘、网络和已登录的采集工具必须可用。网页 API、数据库和邮件监控在云端独立运行。当前没有把本机采集迁成全天在线的云端作业。
- 修改仓库不会自动更新运行副本。采集空闲时执行 `python3 scripts/install-scheduler.py`，安装器验证锁、切换副本并保留一个回退版本；禁止绕过锁覆盖正在执行的代码。
- 本机状态在 `~/.local/share/prompix/content/status.json`，运行日志在 `~/.local/share/prompix/daily.log`。云端 `/status` 只接受私有 Bearer 密钥；查看告警时同时核对 `lastSuccess`、`lastPublication`、`lastAddition`、`incident` 和 `pendingNotifications`，不能只看脚本退出码。
- 失败恢复保留已用预算、未决请求和审核记录。不要删除账本、伪造成功心跳或清除暂缓决定以增加收录量。Skill 包达到安全边界或许可不确定时保持候选，不自动降级为全文收录。
- 当前动态 Skill 适配器覆盖 X/GitHub 发现的公开、完整 MIT 包；其他站点、许可或平台专有运行格式需要单独接入，不能把外链发现说成已完成任意网站的通用采集。
