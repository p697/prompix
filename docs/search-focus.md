# 搜索 Tab 聚焦与本地搜索（2026-10-16）

## 已复现的问题

在 `3779feb` 上新增不点击输入框的 UI 回归：进入搜索后直接在 App 上输入并提交，切到收藏，再点击搜索。首次键盘出现，第二次等待 3 秒仍无键盘。此前的测试都先点击输入框，掩盖了自动聚焦失败。

`RootView` 原先把 `searchable(isPresented:)` 当作焦点状态。搜索提交后键盘可以收起，但搜索界面仍处于 presented；返回时再次写入 `true` 不能重新请求焦点。iOS 17 的旧 Tab 分支也没有选择后的激活处理。

## 修复

- Tab 选择产生独立的激活请求，搜索页面挂载后处理；离开页面取消未完成请求。iOS 18+ 使用 `FocusState` 和 Apple 的 [searchFocused](https://developer.apple.com/documentation/swiftui/view/searchfocused(_:))，把搜索界面呈现与输入焦点分别管理。已处理的请求不在详情关闭后重复执行。
- iOS 17 重新准备搜索呈现状态，并屏蔽程序收起时的文字清空。用户主动清空／取消搜索仍生效。
- 查询文字移至 `SearchView`，输入不再驱动根 Tab 的状态更新。
- 服务器搜索正常时不计算本地兜底全文结果。确实需要旧版／离线全文搜索时，200 毫秒合并输入后在后台执行；切换查询、分类、目录或离开 Tab 会取消旧工作，旧结果不能覆盖新查询。
- 空查询页的本地作者推荐也在后台计算，按目录和推荐日期复用；同一轮布局只读取一次结果，避免反复分组与排序阻塞首次进入搜索。
- 搜索顺序、多词匹配、译文、类型筛选、最近搜索、服务器搜索的既有防抖和缓存策略保持原有语义。

Apple 的[搜索激活说明](https://developer.apple.com/documentation/swiftui/managing-search-interface-activation)明确区分了搜索界面保持展开与输入框失去焦点的情况。

## 验证范围

使用仓库外已发布的 465 条多语言目录（10.56 MB 投影）进行 Debug 模型测量：全文扫描三种查询分别为 101、108、96 毫秒，作者推荐计算为 114 毫秒。旧实现会在 UI 计算过程中同步执行，作者横栏一轮还会读取多次；新实现将这些计算移出主线程。此测量是模拟器上的计算成本，不是 Release 帧率或真机 Tab 切换耗时。

使用独立 `Prompix Search QA` 模拟器；当前机器可用的 iOS 27.1 runtime 只支持 Duo，使用收起形态验证。没有安装或改动用户手机，没有更改已有验收模拟器。iOS 17/18 与普通 iPhone 的真机表现尚未在本轮重测。

修复前后的 `.xcresult` 和日志位于开发 SSD 的 `Prompix-Codex/Evidence/search-focus-*`。性能计算的移出主线程及按需执行，不等于已证明用户手机上每次 1–2 秒停顿的唯一原因；真机卡顿幅度需要同设备测量。

可选的目录成本与大目录 UI 回归通过 `TEST_RUNNER_PROMPIX_SEARCH_BENCHMARK_CATALOG=<仓库外 catalog.json 绝对路径>` 启用；未指定时跳过外部目录测试。大目录 UI 使用新的 UUID 沙箱，不覆盖默认收藏和草稿。
