# 0.10.0（40）：创作者发现

首页不再沿用作品总数排行榜。新客户端从完整目录请求推荐，优先展示有可用图片预览或网页演示的图片、视频、网页创作者，再显示少量视觉作品的混合作者，最后是纯文本作者。视觉作品至少占一半的作者进入第一档；同档按 UTC 日期和稳定作者身份计算固定轮换顺序。作品必须先通过既有收录审核；这不是人工精选或新的审美评分，也不保证每天每位作者都曝光。作品总数不会为推荐加分。

首页最多展示 12 位推荐作者，代表作品预览配合作者头像和姓名。视频、网页使用简洁类型图标，不在小缩略图中显示虚构时长。全量列表的每行也带代表作品，用户进入主页前即可判断大致风格。

“查看全部”提供图片、视频、网页、文本、Skill 筛选，以及推荐、最近更新、作品数量、名称排序，可与姓名／账号搜索组合使用。所有条件在数据库执行，每次最多 30 位作者，继续浏览按游标加载；不是客户端对当前一页重排。按类型筛选后的数量是对应类型作品数，进入作者主页延续该类型，可切回全部。最近更新按作者最近新收录的作品排序，不让翻译修改冒充新增；名称使用服务端统一大小写折叠顺序，不承诺跨语言拼音排序。

筛选、排序和搜索改变后立即隐藏旧范围结果；已有同范围缓存可以继续浏览。列表原生下拉刷新会重新请求当前条件，刷新失败保留现有结果并原位重试。缓存按条件和日期隔离，重开缓存不会复用旧分页游标。辅助字号使用纵向作者信息与自适应菜单排布。

## 服务端与安全

- 旧版 `/v3/creators` 请求和原有游标继续工作。新客户端显式传 `sort=recommended|latest|count|name`，可组合 `kind` 和 `q`。
- `release_creators.discovery` 保存不可变的分类数量、视觉作品数量和最新位置摘要。发布事务内的 invoker trigger 自动生成；旧发布运行副本也会触发，无需额外定时任务。历史已发布版本一次性回填。
- 新游标签名绑定查询条件、发布版本、轮换日期和排序键。跨午夜、并发发布和下架不会使幸存作者越过原有分页边界。仍执行已有 RLS、下架检查、请求速率与字节限制。
- 每个返回作者最多带一张轻量卡片，没有正文或 Skill 文件。下架记录已知后，客户端也不再展示内存中该作品的作者预览。
- 函数使用固定空 search_path、SECURITY INVOKER，只有发布角色可调用准备函数，读者与匿名角色不能执行。没有提高 Worker 或 App 权限，也没有引入外部付费服务。

## 验证记录

证据位于开发 SSD `Prompix-Codex/Evidence/CreatorDiscovery/`。

- `native-ui-2.xcresult`：245 项原生测试执行，242 通过、3 项环境限定跳过；3 项创作者 UI 流程通过，覆盖组合筛选／排序／搜索、进入主页保留类型、空结果、搜索竞态、失败重试、缓存与已知作品先呈现。
- `server-tests.log`：新查询验证与数据库整合测试通过，覆盖四种排序与所有类型的全量分页、每日稳定／次日轮换、跨午夜继续分页、游标篡改／过期／条件错配、并发发布、下架及旧版兼容。
- `benchmark-result.json`：托管 PostgreSQL 独立事务内的 10,000 条合成作品、500 位作者、30,000 条译文；真实只读角色下，三轮新创作者查询执行时间约 127–226ms。含 RLS 与预览读取，不含客户端网络、图片下载或 UI 时间。所有测试 schema/data 事务回滚。
- 九语文案完整性及 TypeScript 类型检查通过。数据库安全 advisor 无新增告警，读者与匿名角色不能执行元数据准备函数。
- 本机并发 PGlite 测试首次遭遇 Node/V8 `Check failed: end > addr` 进程崩溃，保留原日志；新测试单独通过，最终全套串行重跑 528 项全部通过（`full-tests-serial.log`）。

上线顺序为数据库增量迁移、Worker 向后兼容发布、原生客户端。Worker 回滚不需要移除新增列或触发器；它们不改变旧版接口。生产当前首五位推荐均为带图片作品的创作者，未把 Expo/OpenAI 固定到推荐前列。实际身份随日轮换和新增收录变化。
