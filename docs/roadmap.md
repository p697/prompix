# 路线图

## 里程碑

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| M0 | 运营 Agent MVP、管理后台、首批 2–5 千条内容、网页版骨架 | 见 [ops-agent.md](ops-agent.md) 第 12 节 |
| M1 | iOS v1：设计稿 V2 的 10 屏、离线收藏、一键使用、埋点、TestFlight 内测 | 见下文"M1 验收标准" |
| M2 | App Store 上架（除中国大陆）、网页版上线；运营 Agent 从人工审核切换为自动上架加抽检 | 通过审核；连续两周日报无未处理异常 |
| M3 | Android 原生版、日语本地化 | — |

## M0 任务拆分（建议顺序）

1. **仓库结构**：pnpm 工作区，包含 `agent/`、`admin/`、`packages/schema/`；TypeScript、代码检查；CI 跑类型检查、测试和密钥扫描。
2. **数据库与管理后台**：本机 Postgres（Homebrew）加 Payload CMS 3，建立 [ops-agent.md](ops-agent.md) 第 4 节的集合、角色和 Agent 专用的 API Key。
3. **共享数据结构**：在 `packages/schema` 里用 Zod 定义内容条目、来源和快照格式，同时导出 JSON Schema 给 iOS 使用。
4. **命令行骨架**：`prompix-agent` 支持 run、pause、resume、status、service；配好 launchd；用数据库锁防止重叠运行；输出结构化日志。
5. **连接器**：
   - prompts.chat（CSV 或 API）；
   - ClawHub 公共 API，同时取平台检测结论和 commit；
   - 许可明确的 GitHub 仓库，用条件请求只拉变化的部分；
   - X 官方 API 关键词检索，遵守开发者条款。
6. **处理与闸门**：标准化、去重（内容哈希、近似重复、X 帖子 ID）、许可闸门。
7. **模型判断**：DeepSeek JSON 模式加 Zod 校验；用标准样本评测；和通义千问视觉模型做看图对比。
8. **媒体处理**：图片生成多种尺寸（sharp）、视频生成预览（ffmpeg）、生成模糊占位图，上传到 R2。
9. **快照发布**：生成 SQLite 内容库和版本清单 → 发布到 R2 的预发布位置 → 自动检查 → 切到正式；失败自动回滚。
10. **日报与告警**。

## M1 任务拆分

1. Xcode 工程（`ios/`），最低支持 iOS 17；SwiftUI 为主，瀑布流用 UIKit。
2. 数据层：GRDB、内置种子快照、增量更新、FTS5 全文搜索。
3. 首页（瀑布流、频道标签、分类入口）、分类页、搜索页。
4. 图片和视频详情页、一键使用面板、交接引导；接入远程配置。
5. Skill 详情页和获取面板。
6. 收藏与合集（存在本机）。
7. 埋点（PostHog）和崩溃监控（Sentry）。
8. 设置和"关于"页：内容许可、下架方式、非关联声明、隐私政策。
9. TestFlight 内测；按 [handoff.md](handoff.md) 第 6 节做真机测试。

### M1 验收标准

- 10 个界面都能用真实快照数据跑通，导航与设计稿一致。
- 瀑布流在中端机型上滚动流畅，同屏最多播放 2 个视频，滑出即停。
- 断网时可以浏览已缓存的内容和收藏。
- 一键使用：四个 App 在真机上按 handoff.md 的策略工作；失败时能退回"复制 + 打开"。
- 无崩溃地完成 TestFlight 内测一周。

## 风险与应对

| 风险 | 应对 |
|---|---|
| 样图的权利属于创作者 | 只用许可明确的仓库，署名并链接原帖，几小时内处理下架 |
| App Store 审核（4.2.2 内容聚合、5.2.2 第三方内容授权） | 用原生功能（离线收藏、一键交接）体现价值；每条内容都有授权依据台账 |
| AI 厂商修改深链规则 | 链接模板远程配置，失败自动降级，厂商更新后做回归测试 |
| 模型结构化输出不稳定 | JSON 模式加代码校验，失败的进人工队列 |
| 内容新鲜度过度依赖单一来源 | 多个来源并行，加上 X 官方 API |
| 生产环境的国际网络不稳定 | 代理配置、自动重试和告警 |
| Skill 投毒 | 只展示、不执行；固定 commit；展示来源平台的检测结论 |
