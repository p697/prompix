# 路线图

更新：2026-10-12。0.2.0 用户验收为勉强及格。当前推进 **0.3.0 国际化、创作者、Skill 与原生发现体验**，本阶段交付真实模拟器演示，不向用户手机安装。设计方向已确认，继续自主实现和验证，不把旧候选包签名、旧手机接线或内容扩量当成产品验收通过。当前执行记录见 [next-release.md](next-release.md)，范围变更见 D-42。

## 1. 分工与推进原则

- 研发负责人主导产品细化、设计研究、实现、采集、翻译、模拟器验证、PR 与交付演示；用户提供 brief 并验收。
- 使用当前 Mac 的开发与运行资源。复杂推荐 Agent、独立数据库和用户账号系统不是当前阶段的前置条件。
- 按真实流程验收：发现 → 作者／专题 → 内容 → 原文／译文 → 编辑／复制 → 收藏 → 再次使用。四类 Prompt 保持覆盖，Skill 提供明确的阅读与外部使用方式。
- 每项代码修改在独立 worktree／分支完成，通过 PR 检查、合并和清理；Xcode 构建、模拟器测试串行执行。
- 全量内容与翻译缓存、头像、运行账本、截图和录像保存在仓库外；文档不把待发布目录写成线上结果。

## 5. 0.3.0 之后的上架工作

用户认可模拟器演示后，再集中准备适用的签名或 TestFlight、真实设备性能与网络检查、商店截图和预览、隐私与来源说明、年龄评级和审核操作说明。当前不安装到用户手机，也不因旧签名条件要求用户接线。商店材料必须匹配最终构建与已发布内容，不能沿用旧 build 的截图作为新版证明。

海外优先、首版不含中国大陆的方向保留；上架地区、主体和账号状态在提交前核实。已有中英文官网和帮助页，客户端九语不自动代表网站与商店材料也已九语化。Apple 编辑推荐是品质目标，无法由内部评分、截图或测试保证。

## 6. 风险与处理

| 问题 | 处理 |
|---|---|
| 首页入口多但内容不突出 | 让作者和专题服务于发现，筛选时直达结果，检查第一屏实际内容与点击路径 |
| 作者错误合并或来源混淆 | 以稳定身份分组，区分聚合平台和原作者，缺失字段不猜测 |
| 翻译改变指令或代码 | 保留原文、保护片段与指纹校验、完整字段验证、语义抽检和明确 AI 译文标示 |
| 翻译重跑费用失控 | 请求账本、持久预算、锁、断点缓存和失败限次，CLI 与 API 额度分别记录 |
| Skill 文本被误认为可运行包 | 展示源目录和文件要求；阅读、复制和前往安装说明不冒充已安装或已执行 |
| 缓存更新损害个人数据 | 收藏独立快照、草稿按语言隔离、原文一致才补全元数据、损坏文件保留与恢复 |
| 扩量超过目录容量 | v1 仍设 1,000 条／10 MB 上限，超限明确失败；容量演进另做分页或分片设计 |
