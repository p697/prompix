# 路线图

更新：2026-10-11。交付目标：用户能在真机安装并验收的原生 iOS 多模态 Prompt App，之后推进 App Store 上架。先确认设计，再开始客户端开发。

## 1. 分工与推进原则

- 项目负责人（研发 Agent）主导范围收敛、设计方案、实现、采集、模拟器与真机验证准备、PR、发布准备和迭代；向用户展示可验收结果。
- 用户提供 brief、确定设计方向和验收产品，完成必须由账号所有者处理的签名、主体和发布手续。
- 可以使用当前电脑的开发工具、模拟器与计算资源；不因资源可用就搭建首版不需要的系统。
- 每阶段用真实体验验收，四类内容始终在范围内。设计确认是明确关口，未收到确认不开始客户端开发。
- 每项修改使用独立 worktree／分支和 PR；按仓库规则检查、合并与清理。

## 2. 里程碑

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| M0 设计确认（当前最高优先级） | 具体 App 参考、2–3 个视觉方向、核心页面方案 | 用户明确选择方向，并确认四类内容的浏览体验；不以旧 V2 稿代替确认 |
| M1 可运行纵向版本 | 原生 iOS、四类真实种子内容、首个采集适配器与本地目录 | 模拟器跑通逛 → 详情 → 编辑／复制 → 收藏 → 返回；全部／文本／图片／视频／网页可用 |
| M2 真机验收版 | 轻量发布更新、第二个独立来源、搜索筛选、缓存分享、签名安装包或 TestFlight | 用户能安装到真机；四类完整闭环、异常处理与性能通过检查 |
| M3 上架 | 商店素材、隐私与支持页、审核提交 | 真机验收通过，阻断问题解决，所需账号手续齐备；通过审核后发布 |
| M4 后续迭代 | 内容扩展、Android Native、按需求评估 Skill 与运营自动化 | 依据真实使用反馈另定范围，不默认把完整旧 Agent 方案全部实现 |

## 3. M0：先定设计感觉

1. 比较手机淘宝、小红书的发现方式，以及其他内容发现产品的卡片、排版和交互；明确借鉴对象与取舍。
2. 提供 2–3 个可比较的方向，使用同一组文本、图片、视频、网页样例，方便判断配色、信息密度与品位。
3. 优先确定首页、四类卡片、详情与收藏的感觉；保证文本卡片有吸引力，不能做成纯指令列表。
4. 用户选择后细化字体、间距、颜色、封面策略、导航和动效；确认后更新设计规范，再启动 M1。

**设计验收**：无需搜索也能发现想点的内容；卡片能看懂用途和类型；四类内容混排协调；有淘宝／小红书式的浏览欲望，同时保持克制、精致和原生操作。设计方向未确认前，只做方案与设计验证。

## 4. M1：最小完整体验

1. 建立 `ios/`、`ingest/`、`packages/schema/` 与适用的 CI；采用合成样例做协议测试，第三方内容不提交仓库。
2. 定义统一条目与发布协议，区分内容类型、预览形式、模型、工具和来源。
3. 先实现一个可用的来源适配器，支持手动导入与原创内容；校验、去重和错误报告可运行。
4. 准备建议不少于 40 条的首轮验收样本，每类至少 10 条；包含娱乐文本、实用文本、图像、视频、建站或交互案例。数量是开发验收建议，不是用户增长目标。
5. 按确认后的设计完成发现流、详情预览、简单编辑、复制、本地收藏与返回位置保持。
6. 用模拟器检查小屏、动态字体、内容过长、慢网和空状态；把截图／录屏与构建结果用于阶段验收。

**M1 验收**：四类都可浏览、看示例、复制和收藏；视频真正能播放；网页案例有截图／演示和完整 Prompt；文本有用途与示例，不是填充用的少量附属内容。此阶段不用完整后台、数千条内容或推荐 Agent 作前置。

## 5. M2：可安装的真机验收版

- 增加第二个独立来源适配器，验证统一格式能接不同来源；首批内容建议扩展至 200–500 条，每类持续有有效覆盖，不为凑数收录重复条目。
- 完成关键词搜索、类型／用途／模型筛选、编辑专题与相关内容；没有足够行为数据时不做虚假热门榜。
- 发布到自有存储，验证目录更新、校验失败回退、条目移除、图片缓存和视频播放。
- 完成系统分享、工具链接与复制兜底；记录实际测试过的工具、系统版本与行为。
- 接入必要观测，补齐设置、隐私、支持与来源入口。
- 在 Xcode 中检查可用签名团队与设备安装条件。交付优先使用 TestFlight；条件未齐时，可用已具备的开发签名在登记设备安装。明确安装范围和有效期，不能把模拟器包或未签名 IPA 当真机交付。
- Apple 账号、证书或设备信息缺失时，提供具体缺项并由用户完成必要步骤；继续不依赖签名的开发与模拟器测试。

### M2 验收清单

- 用户能在真机安装；首页直接进入内容，无登录门槛；四类内容均可独立完成发现、查看、复制、收藏和再次使用。
- 首页滚动、原生返回、图片缩放、视频播放和系统分享可用；详情返回不丢位置；按代表性较旧设备或可用真机记录帧率、内存和异常情况。
- 同时至多一个列表视频静音播放；离屏／后台停止，减少动态效果与低数据模式关闭自动预览。
- 断网可打开收藏文本和缩略图并复制；完整视频和在线网页不可用时有清楚状态。清理缓存不删除收藏文本。
- 更新失败保留旧目录，重复采集不重复入库；移除记录在下次成功联网刷新后作用于目录、缓存和收藏。
- 覆盖长文本、中文、emoji、换行、缺失媒体、搜索无结果、未安装目标工具；不把链接打开成功当成预填或生成成功。
- 记录一轮连续使用内测与问题清单，解决阻断和高优先级问题后交由用户验收；模拟器结果不替代真机测试。

## 6. M3：上架准备

用户真机验收后，负责人准备商店文案与截图、隐私说明、支持页面、内容来源说明和审核操作说明。保持原生工具价值，不要求用户必须装另一个 App 才能浏览、收藏或复制。

沿用海外优先、首版不含中国大陆的方向。开发者主体、签名和上架地区在提交前核实；审核结果不提前保证。完整 SEO 网站不是 App 上架前置。

## 7. 近期推进顺序

- [ ] **最高优先级：与用户确定设计方向。**
- [ ] 确认核心页面和四类卡片，再初始化 iOS 工程。
- [ ] 选择首个稳定来源，完成统一格式与四类种子内容。
- [ ] 完成 M1 模拟器纵向演示，再推进 M2 真机安装。
- [ ] 在需要签名交付前确认 Apple 开发者账号／团队与设备条件。
- [ ] 在需要在线更新前配置对象存储、域名和必要凭据。

不要求预先购买 X API、配置 DeepSeek／视觉模型、搭建 Postgres／Payload 或部署 Mac mini 常驻 Agent。

## 8. 重点风险与处理

| 问题 | 处理 |
|---|---|
| 内容广但不好逛 | 优先验收卡片、专题、四类覆盖和内容质量，按类型观察详情与复用表现 |
| 视频拖慢首屏或耗流量 | 封面优先、受控预览、缓存上限、低数据模式和真机验证 |
| 依赖单一来源或解析变化 | 小型独立适配器、保留来源版本与失败报告、手动导入兜底 |
| 目标工具行为变化 | 复制始终可用，逐条目配置并真机验证，不承诺自动生成 |
| 设计未经确认就固化 | M0 明确通过后再开始客户端开发 |
| 签名条件影响真机交付 | 提前核实团队与设备条件，区分模拟器验证与真机安装 |
