# 决策记录

这里记录 Prompix 的关键决定。新决定追加在末尾；被推翻的条目标记为"已替代"，并指向新条目。以下条目都在 2026-10-11 讨论确认。

## D-01 不做"抓取各提示词站并全文展示"

- **决定**：只全文展示许可明确允许的内容；其他内容只放元数据、自写摘要和原文链接；禁止抓取的站点不收录。
- **原因**：
  - 内容并不稀缺：开放生态里图像提示词背后只有约 1 万个不重复的 X 帖子，而且被各仓库大量重复收录。
  - 抓取后全文展示会同时触碰版权、站点条款、中国《反不正当竞争法》和 App Store 审核规则（4.2.2、5.2.2）。"免费、非商业"挡不住这些风险。
  - 真正的瓶颈是**信任**（好不好用、是不是原文、能否合法展示）和**交接**（怎么送进用户正在用的 AI App）。

## D-02 定位：视觉优先的提示词和 Skill 货架

> 状态：已被 D-20 替代。

- **决定**：主线用户是视觉创作者。体验做成手机淘宝式：瀑布流、分类、搜索、推荐，图片和视频是第一视觉元素。Skill 为副线。
- **原因**：图片和视频提示词最贴合手机：素材在相册里，生成器本身就是手机 App，需求有明显的热点脉冲。通用文字提示词库正在退潮。

## D-03 名称：Prompix

- **决定**：产品名 Prompix（prompt + pix），一听就是"看图找提示词"。
- **补充**：美区 App Store 没有同名应用。prompix.com 和 prompix.app 已被他人注册，prompix.ai 在 2026-10-11 查询时还未被注册。

## D-04 独立、开源、免费

- **决定**：独立项目，不与任何公司合作；代码以 MIT 许可开源；v1 无广告、无内购。
- **补充**：公开仓库为 https://github.com/p697/prompix 。

## D-05 市场：海外优先，除中国大陆外全部上架

- **决定**：v1 在除中国大陆外的全部地区上架，以北美作为口味基准和营销重点；中国版以后作为单独的产品来做。
- **原因**：
  - ChatGPT、Claude、Gemini、Grok 都没有在中国区 App Store 上架，国内版的核心功能不成立，还有合规风险。
  - 用户主要在美国以外：例如 ChatGPT 的下载约 11% 来自美国、21% 来自印度。只做北美，等于主动放弃大部分做图用户。

## D-06 平台：iOS 原生先行，Android 原生后做，网页版同步

> 状态：平台原生方向保留；网页版同步要求已被 D-21 替代。

- **决定**：iOS 用 SwiftUI，瀑布流用 UIKit。Android 以后用 Kotlin + Jetpack Compose 单独开发。网页版用 Next.js 静态生成。
- **原因**：研发由 AI Agent 完成，维护两套原生代码的成本可以接受；原生在大量图片和视频滚动的性能、系统能力（分享扩展、键盘、快捷指令）上都最好。

## D-07 视觉方向：V2 组合方向（暗色）

> 状态：已被 D-24 替代；视觉方向待本轮确认。

- **决定**：以暗色沉浸画廊为基调，首页结构采用淘宝式的搜索和分类入口，Skill 和来源信息采用"可信度"写法。界面稿在 `design/v2/`。
- **过程**：先评估了三个方向：A 货架逛街（亮色、信息密度高）、B 沉浸画廊（暗色、视觉最大化）、C 精选专题（编辑推荐加分类搜索），最后组合成 V2。

## D-08 一键使用的实现策略

> 状态：已被 D-23 替代；历史链接不代表真机验证结果。

- **决定**：
  - ChatGPT、Grok 用 App 官方认领的通用链接直接带入提示词；
  - Gemini（iOS）和 Claude 复制到剪贴板后打开；
  - Gemini（Android）用系统分享带入；
  - 只预填、不自动发送；
  - 链接模板放在远程配置里，打开失败时退回"复制 + 打开"。
- **原因**：我们直接读取了四家 App 公开的通用链接配置文件，逐个核实了能力；四家都不支持"提示词 + 图片"一次带入。详见 [handoff.md](handoff.md)。

## D-09 v1 不做账号、社区、App 内生成

- **决定**：收藏存在本机；不做评论、投稿、点赞；不在 App 内调用模型生成内容。
- **原因**：降低合规和审核负担（用户生成内容的审核义务、生成式 AI 的监管要求），也让免费模式可以持续。

## D-10 v1 不做自产样图和多模型实测

> 状态：部分被 D-22 替代：允许原创 Prompt 与必要示例，批量自产媒体和跨模型评测仍后置。

- **决定**：样图用创作者公开发布、并经许可明确的上游仓库收录的图片，署名并链接原帖。图片转存为多种尺寸，保证加载性能；作者要求即下架。设计画布里的"Tested ×3"标签和多模型对比条不进入 v1，`design/v2/` 已移除。
- **原因**：主流提示词站基本不自己出图，大多转存或热链 X 原图，很多提示词是逆向推出来的；只有少数库做过小规模复测。自产样图需要调用 Gemini、OpenAI、xAI 的出图服务，成本和可用性以后另议。

## D-11 内容来源白名单

> 状态：首版接入范围已被 D-22 替代；来源基本原则保留。

- **决定**：
  - ClawHub（Skill，MIT-0）；
  - 官方 Skill 仓库（许可按文件夹判定）；
  - prompts.chat（CC0）；
  - 许可明确的图像提示词仓库；
  - X 官方 API（按量付费）。
  
  不抓取禁止抓取的站点。详见 [content-policy.md](content-policy.md)。

## D-12 Skill 的收录与风险展示

> 状态：首版范围已被 D-20 替代；本条保留供后续 Skill 阶段参考。

- **决定**：Skill（包括带脚本的）和 MCP 卡片都收录；只展示来源平台自带的检测结论，我们自己不另作安全声明；平台已隐藏、拦截或判为恶意的不收录；安装命令固定到收录时的 commit。
- **原因**：2026 年 Skill 市场出现过大规模投毒，各平台的检测结论并不一致。固定 commit 可以防止作者在收录后改动内容。

## D-13 内容运营交给运营 Agent

> 状态：首版已被 D-22 替代；复杂运营 Agent 后置。

- **决定**：运营 Agent 每天闭环完成发现、评估、包装、上架、排货架、发布、学习、维护和汇报；人类通过管理后台查看和修改。上线头两周全部进人工审核，阈值校准后改为自动上架加抽检。

## D-14 运营 Agent 选型：代码优先（TypeScript）

> 状态：首版已被 D-22 替代；保留为未来备选。

- **决定**：
  - 用 TypeScript（Node）编写确定性流水线，大模型只负责判断；
  - 处理外部内容的模型调用不给任何工具，只返回 JSON，并用 Zod 校验；
  - 调度用 launchd；暂停开关和运行记录存在 Postgres；
  - 管理后台用 Payload CMS；
  - 不用 OpenClaw、Hermes Agent 作为运行时，也不用 Prefect。
- **原因**：
  - OpenClaw 和 Hermes 面向"一个可信的人在聊天里指挥的个人助理"，默认权限宽，官方不把提示词注入算作漏洞；而且迭代极快，定时任务有未修复的缺陷。我们的场景是无人值守、每天大量读取不可信内容，两者的前提都不符合。
  - Prefect 在服务重启后会重置界面上的暂停，而且它的运行界面和管理后台功能重复。
  - 用 TypeScript，Agent、管理后台和网页版可以共用一套数据结构。
- **备选**：Python + Pydantic AI + Prefect。

## D-15 运行环境

> 状态：首版已被 D-22 替代；不要求常驻 Mac mini。

- **决定**：开发阶段在 MacBook 上调试，生产环境放在 Mac mini 上。Agent 支持代理配置，确保能稳定访问 GitHub、X 和 Cloudflare。生产环境用系统级 LaunchDaemon 运行，不依赖用户登录。

## D-16 模型

> 状态：首版已被 D-22 替代；不要求模型调用。

- **决定**：默认用 DeepSeek（当前为 V4.1 flash，做判断时关闭思考模式）负责判断、打标签和翻译。看图能力先和通义千问视觉模型用标准样本对比，效果相当就只用 DeepSeek。模型统一通过 OpenAI 兼容接口接入，可以替换。

## D-17 使用 X 官方 API

> 状态：部分被 D-22 替代：X API 是可选接入，不是首版前置或费用承诺。

- **决定**：允许使用，按量付费，预计每月约 30–100 美元。遵守 X 开发者条款，例如原帖删除后同步删除。

## D-18 研发流程

- **决定**：研发主要由 AI Agent 完成。每个任务在独立的 worktree 和分支里进行；PR 通过 CI 后可以由作者自行合并；密钥只放在仓库外的 `~/.config/prompix/`。详见 [AGENTS.md](../AGENTS.md)。

## D-19 数据与监控

> 状态：部分被 D-23 替代：不建设 Agent 反馈与 LLM 数据库。

- **决定**：
  - PostHog 负责匿名埋点和转化漏斗，同时作为运营 Agent 的数据输入；
  - Sentry 负责崩溃监控；
  - 大模型调用记录先存在 Postgres，需要更细的追踪时再接 Langfuse 云服务。

## D-20 首版是多模态 Prompt 发现 App

- **决定**：文本、图片、视频、网页四类均进入首版；模型、工具、来源与预览形式独立组织。网页包含建站、交互页面、应用与小游戏案例。
- **核心原则**：让用户像逛手机淘宝和小红书一样发现有意思的 Prompt。没有搜索目标也能逛；卡片展示用途与效果，文本用示例回答／对话吸引用户。
- **范围**：浏览、专题、搜索筛选、详情、编辑复制、系统分享、本地收藏。Skill／MCP、账号社区、App 内生成和个性化推荐后置。
- **替代**：D-02 的视觉创作者优先与少量文本定位、D-12 的首版 Skill 范围。产品名 Prompix 保留，但不再用图片专属描述限制定位。

## D-21 原生客户端先行，完整网页产品后置

- **决定**：iOS 原生，SwiftUI 为主，按性能需要使用 UIKit 和原生媒体能力；Android 后续用 Kotlin + Jetpack Compose 独立原生实现。共享内容与协议。
- **说明**：HTML 是设计参考，不是 App 技术路径。网页 Prompt 是首版内容，不等于要同步开发完整 Prompix 网页产品。
- **交付**：先模拟器验证，再交付具备签名安装条件的真机验收版；支持、隐私等上架页面按需准备。
- **替代**：D-06 的网页版同步与网页先上线要求，原生平台方向保留。

## D-22 自建轻量采集，复杂运营 Agent 后置

- **决定**：TypeScript 确定性脚本接入允许来源的 API、公开数据和网页，完成提取、去重、校验、媒体处理与版本化 JSON 发布；先手动运行，按需要增加简单定时任务。
- **供给**：外部收录、原创、允许的整理改编并行；保留来源与署名，第三方内容不进仓库。竞品研究不自动成为采集授权。
- **边界**：不要求 Postgres、Payload、常驻 Mac mini、付费 X API、模型评分与每日推荐 Agent；不建设批量媒体生成和多模型评测平台。
- **替代**：D-13 至 D-16 的首版运营依赖，以及 D-10、D-11、D-17 的相关首版范围。旧 Agent 方案保留为后续备选。

## D-23 用简单的发现和复用闭环验收

- **决定**：首版用编辑精选、最新、用途分类和简单相关内容组织发现，不做个性化、地区推荐或虚构热度。每条都能复制、分享、本地收藏，目标工具预填经真机验证后按需启用。
- **观测**：按类型看曝光、详情、复制、分享、收藏与回访；不上传用户编辑内容，不把工具打开当作生成成功。保留必要分析与崩溃监控，不建 LLM 数据库。
- **替代**：D-08 的预填既定承诺、D-19 的 Agent 反馈和模型追踪要求；D-05 的首版地区排序不再要求，海外市场方向保留。

## D-24 先确认设计，再开始客户端开发

- **决定**：用户强调设计感和品位。先以具体 App 为参考，比较视觉气质、信息密度、四类卡片和核心页面；由用户明确确认后再开始客户端开发。
- **当前状态**：设计方向尚未确认。旧 V2 十屏与暗色亮绿方向仅作历史参考，不是本轮定稿。
- **分工**：研发负责人主导设计、实现、模拟器测试和安装交付准备；用户给 brief、选择设计和真机验收。可使用当前电脑资源；签名交付仍需实际 Apple 账号／团队与设备条件。
- **替代**：D-07 的视觉定稿。设计确认成为路线图 M0；后续是可运行版本、真机验收、上架。


## D-25：确认「轻盈发现」，启动原生实现（2026-10-11）

用户明确选择小红书的双列浏览结构与 Cosmos 的克制、有品位感，授权开始落地。D-24 的设计确认关口已通过。原生 iOS 与尽量使用系统组件是硬要求；App Store 编辑推荐的质量是打磨目标，不是保证推荐的承诺。

首轮采用 SwiftUI 原生双列懒加载、NavigationStack、TabView、系统搜索／输入／分享、AVKit、UIScrollView 缩放。24 条原创 Prompt（每类 6 条）用于可安装设计预览，采集草稿不未经编辑直接进入 App。视频先点击播放，复杂列表自动播放后置。中文验收版先验证体验，海外发行的英文界面随后补齐。

## D-26：区分设计预览与内容上线（2026-10-11）

0.1.0 使用内置原创内容，不依赖线上服务。图像实际输出、文本编辑示例、程序视频与网页封面均明确标注。允许在独立预览页用 WebKit 打开仓库内自制网页作品；不承载 App 主界面、不执行采集来的网页代码，禁用 JavaScript。

轻量采集首个适配器读取 prompts.chat 的公开 CC0 CSV，并在仓库外保留草稿、作者与版本；发布命令目前仅生成本地版本化候选，不宣称已有线上发布／客户端远程刷新。M1/M2 尚需真实视频与更多网页案例、编辑后的多来源内容、线上更新与发布准备。


## D-27：从设计预览转入真实内容闭环（2026-10-11）

用户已在 iPhone Air 体验 0.1.0：认可大方向，但认为图标尤其底部三个 Tab 不够精致，距 App Store 编辑推荐标准仍远。继续保持「轻盈发现」，重绘图标并持续打磨原生体验。研发负责人自主推进模拟器开发、测试与完整功能，短期不反复要求用户验收。

用户授权在这台 Mac 上运行每日采集，使用付费 X API、配置服务并创建项目凭据。采用确定性 TypeScript 管线和本机 launchd，每天 08:00 执行；X 先限量发现候选，开放数据来源可按编辑规则自动发布。复杂运营 Agent 仍后置。账户付款信息等必须本人处理的步骤再请求介入。

## D-28：品牌域名与内容服务（2026-10-11）

用户购买并授权使用 `prompix.dev`。品牌官网保留主域名，内容服务部署到 `api.prompix.dev`，使用 Cloudflare Worker + 专用 R2 bucket。采集、候选、密钥与发布控制仍在 Mac 上；App 只访问只读内容接口。真实内容不进入公开代码仓库。

## D-29 持续推进至完整验收交付

2026-10-11，用户要求设立持续目标，由负责人持续完成研发、内容、设计与验证，不得在单次联调或 PR 后停止。以 [完整交付质量关口](quality-release.md) 作为完成条件；沿用已确认的轻盈发现方向和原生 iOS 路线。编辑推荐作为质量目标，不承诺 Apple 的推荐结果。只有确实依赖用户的账号、签名或发布手续才请求介入。

## D-30 让网页 Prompt 对应可操作的原创作品

六个原有网页条目补齐实际 HTML/CSS/JavaScript 作品与真实截图。作品随 App 打包，可离线打开；主界面与操作仍为 SwiftUI 原生。WebKit 仅对显式列出的本地原创文件启用脚本，使用临时数据存储、限制文件访问范围与 CSP；外部链接交给系统打开。网页里的示例状态仅属于当前预览环境，不与 App 收藏或草稿混用。第三方网页不进入这个本地脚本执行通道。

## D-31 文本编辑与预览对应关系

增加 12 条具有具体输入、用途和示例的原创文本 Prompt。社区角色提示词先留在候选库，只有经过编辑的标题、示例和封面才进入发布；编辑记录保存在仓库外并绑定来源正文指纹。网页社区条目还需要实际作品与预览图。图片支持编辑指定与正文对应的预览，不把同帖任意首图默认为该 Prompt 的结果。线上版本排除内置程序视频和占位图，离线原创展示仍如实标注。


## D-32 内容回滚保留下架记录并暂停自动发布

每日发布与回滚使用同一把本机锁。回滚生成新的可校验版本，合并旧版本、线上当前版本和本地下架记录；旧目录保持不可变。激活前写入发布暂停状态，采集仍可继续，修复后显式恢复发布且验证成功才解除。默认回滚命令仅演练，故障报告在仓库外保留；不把手工覆盖 latest 当作可靠回滚路径。

## D-33 官网与原生支持入口

## D-40 未保存的编辑必须有明确退出选择

2026-10-12：存储写入失败时，既要保护已有草稿，也不能让编辑器下滑关闭而丢掉本次修改。编辑器在内容尚未持久化时阻止交互式关闭，提供重试保存，以及原生确认中的继续编辑、复制并退出、放弃修改并退出。后两种退出明确保留此前成功保存的草稿，且不再触发延迟或生命周期保存。实际模拟器录屏发现全局错误弹窗会关闭编辑页，因此草稿错误在编辑器内显示具体原因，不竞争根页面的弹窗。修复在模拟器验证并以 build 4 单独归档，不反复安装用户手机。

## D-49：元数据批准与媒体对应核验必须独立（2026-10-12）

扩充新来源时复查发现，旧自动编辑只收到媒体存在布尔值，不能据此放行图片或视频；已有元数据审批缓存也有相同边界。补充发布前的独立媒体就绪检查，覆盖缓存路径。新条目和变更条目需要完整正文与实际所选媒体的核验记录，绑定内容寻址文件哈希和图集顺序。正文、模型、来源或媒体改变即重新检查；未改变的既有线上快照可按现有保留策略继续交付，不伪造历史视觉审核。

复用单次、受限的每日进程，以实际图片输入完成图集核验，并对短视频记录封面和六个采样帧的覆盖。视频抽帧不能验证音频、连续运动或每帧细节，证据不足暂缓；网页作品不能只凭静态图片批准。模型每日单独最多一次、三条、16图、32,000输入字符，请求先记账。失败或不确定保留旧版，其他已就绪内容继续发布，不引入长期运行的复杂Agent。

## D-50：按语言下载从纯协议迁移开始，保留完整发布与个人数据（2026-10-12）

实现v2原文目录加独立语言文件，保留v1可用版本。发布器仍保有全部语言；只有客户端传输按所需语言拆分，缺译文回到原文，不隐式请求英语。完整源文指纹绑定译文；原文中明确声明可用语言，区分尚未下载与已撤回。新协议先完成纯拆分、验证与完整重组，再接入双通道发布、回滚和原生事务，不能将协议测试通过描述为已经上线。

保持单文件和原文加任一语言文件的10 MB解码上限、32 KB清单和1,000条限制。收藏按完整指纹合并已验证语言，草稿身份不变；快速切换语言必须防止旧任务覆盖新状态。两条发布通道分别校验和激活，并记录中断恢复状态；v2必须有完整的上次发布读取后才可成为保留依据。细节及验收边界见[按语言分发协议](content-protocol-v2.md)。

## D-51：双通道发布先记录精确意图，再恢复未完成工作（2026-10-12）

v2服务器集成采用本机锁和持久发布记录；所有不可变文件上传、回读并完整重组后，先激活v2再激活v1。两次指针写入不是一个事务，状态分别记录。每日发布先续完已有目标再退出，不重新抓取或消耗审核／翻译预算；新下架记录可重建既有目标，其他新内容留待后续正常运行。远端指针变化时停止覆盖，显式回滚可直接替换未完成普通发布并保留其下架记录。

v1超容量后保持最后兼容快照，仅继续下架，不随后续缩量自动解冻。完整v2是后续保留和回滚依据；本地状态缺失不能造成静默退回v1。原文及译文保留原字节，结构校验不得顺手修剪正文而改变指纹。回滚恢复重新检查媒体，保留已有暂停文件；普通恢复只能清除最初选择的同一暂停。此实现不改变原生下载通道，服务器上线和原生接入分别验收。

## D-53：v2每日发布使用独立且保留完整文本的版本身份（2026-10-12）

旧每日流程在schema修剪文本前计算版本号，首次v2初始化则保留已发布的修剪后目录；从同一翻译缓存重建时，可能得到同一旧版本号但不同字节。v2每日版本改用 `edition-v2-<hash>`，对完整原文、全部译文、作者、媒体及下架集合计算稳定对象键顺序的哈希；文本空白和数组顺序仍影响版本，目录发布时间不影响。首次初始化、旧版本读取及旧版发布方式保持兼容，不放宽不可变校验，也不改写旧文件；重跑同一v2内容复用原字节和时间戳。

## D-52：原生按需语言以已验证缓存和个人数据事务激活（2026-10-12）

0.3.2（9）将原生更新接到v2原文与独立语言文件，沿用Granola视觉和iOS App语言偏好。自动刷新补下载App偏好语言；显式选择只请求所选语言，同版本缺包仍可补齐，缺少偏好包不阻止其他已缓存语言离线使用。未提供的语言回到原文，不隐式请求英语。语言文件按哈希暂存并回读，活动索引与目录、收藏、创作者和下架草稿清理共用回滚日志。健康且未变化的刷新不写活动或个人文件，损坏的普通缓存文件仍先修复。非活动文件在暂存结束后按当前磁盘索引清理；共享租约保护并行写入、取消中的暂存及祖先路径别名。MainActor清理保留原文、全部已下载语言与存活租约，任意回滚日志或无效索引阻止删除，只处理规范SHA文件名的普通文件，失败不撤销成功提交。健康静置且清理成功后最多10个活动文件、协议上限约90 MB；待恢复日志、租约或文件系统失败期间不作全局硬配额承诺。五个合成九语版本每次均保留10个文件，148项模型及清理回归干净通过；这是规则验证，不冒称数月使用实测。

详情区分目录和收藏来源。完整源文指纹一致才合并译文，明确撤回与尚未下载分开处理；标题、摘要和封面文案的变化也保留整个旧收藏快照。取消收藏不能让仍打开的详情复活旧语言。语言切换成功前保留当前内容，失败可重试，原文选择取消本次请求；任务代次与来源检查阻止旧响应覆盖新状态，成功的显式安装也取代旧任务。编辑器在打开时固定内容及语言，后台更新不改变草稿基线；下载不改写个人草稿，明确下架才在事务内删除其全部语言变体。

服务器初始化时保留既有346条九语、v1指针与完整内容；此为历史初始化边界，当前两通道已推进到`edition-v2-d8f7fc6af6de6061`。版本身份冲突的PR40修复已合并并安装，网络中断后的恢复和随后普通每日重跑均退出0，同版346条、未冻结v1、待发布记录清除，必需v2完整线上校验通过。模拟器验证包括68→346条升级、收藏与原文／日语草稿及重启保留、英文草稿隔离；全部修复后的当前生产版语言UI复验亦通过，仅中文补日语后恰有3个活动文件、2,435,000字节，旧版文件清除，草稿不变，日语复制仍与预期738字节一致。Release五次进程启动均值3.624秒、三轮滚动峰值均值约135.47 MB，条件为完整英语缓存的346条旧版目录，不是冷启动、FPS或直接版本对比。验收后专用模拟器原9个文件哈希恢复一致。最新签名候选0.3.2（9）来自`8118eeb`，归档与IPA本地严格签名和资源审计通过；本轮未安装或触碰用户手机，最终真机与主观验收另行安排。部署、模型、UI和性能条件分别记录于[协议文档](content-protocol-v2.md)，签名证据见[交付记录](quality-release.md)。

## D-54：每日审核在持久累计预算内连续处理，保留失败隔离（2026-10-12）

此前元数据和视觉各每天一次／三条的工程默认值限制了已发现候选的处理速度，并非用户指定的费用上限。两阶段各改为默认四次请求／UTC日，每次候选、输入字符和附件上限不变；可显式配置0–20次，0禁用新调用。一次正常daily消耗剩余名额内的待办，不依赖反复触发调度器。翻译每日默认从十二次提高到三十六次，现有显式配置仍优先；X维持每天一次搜索／最多十条。

每次审核调用前追加持久预约，完成批次保留决定和实际token记录。旧单次账本迁移后仍占一次；失败、歧义响应、持久化故障或中断预约阻止该阶段当天余下请求，不能因新限额增加而重试；次日重新分配名额。已完成的缓存与审批可复用，每次原始响应分别保存。翻译保留既有累计预约与有界重试行为，不将审核失败策略误写成所有模型调用均不重试。

Codex仅能明确约束请求量、输入、时间和账号额度，不能把未知费用称作每日2美元硬限。审核通过数与实际发布新增仍分开；新网页的实际作品检查、视频连续运动／音频证据、X来源发布接入等门槛不变。此决定定义代码默认与测试边界，不表示已经升级生产运行器或改变真实配置。

## D-55：明确的括号输入指引参与翻译，按字段修复既有译文（2026-10-12）

短方括号不一律等同代码变量。普通正文中明确的中文或英文动作加输入对象，例如要求用户写下想法或输入姓名，作为可翻译指引；括号内部的参数、数字与URL继续递归保护。短名词标签、变量标识、时间码、代码、JSON键与模型参数、图像中的固定文字维持现有边界。当前匹配器不是平衡括号解析器，嵌套方括号的既有匹配范围继续保护，不尝试翻译其中指引，避免把内部标识误当正文。未变化的外语指引只在语种或语法明确时拒绝，允许繁体／日文共用汉字以及含混的拉丁语短句，其他情况依赖精确语义审核。

保护规则变化只改变受影响字段的遮罩哈希，不改原文、完整源指纹或翻译缓存总版本；其他字段与模型来源记录继续复用。既有错误译文按语言、原文字段哈希与译文字段哈希精确失效，不能从同源旧目录继承回来，也不清空共享缓存。外部修复先核对七条明确指引的49个语言记录，使用真实当日剩余额度逐步补齐；其中六条改变遮罩，另一条已是可翻译正文但旧译文仍未翻译指引。这不是声明已执行模型或发布修复。预算不足时保留活动版本，待受影响条目九语言完整、未改原文和技术语法且通过独立审核后才激活新版本，不把暂时缺失的译文当作完整修复交付。

## D-56：X 缺失正文通过有界原帖重取恢复，不放宽草稿或发布门槛（2026-10-12）

现有20条发现来自缺少完整长文与附件字段的旧快照，17条没有明确提示词边界、3条包含无法确认的短链；这些计数不能证明原帖包含完整Prompt。增加显式 `PROMPIX_X_LOOKUP_IDS` 单次运行模式，仅选择缓存里已有的1至10个数字帖ID，通过官方批量原帖查询重取长文、实体链接、附件、作者及会话元数据，替代当天搜索，不增加每天一次的付费读取预算。预约先于请求持久化；失败、部分响应、缺失ID或写入故障仍占用当天名额，不自动重试、翻页或尝试另一套字段别名。新快照记录所选ID、端点与请求身份，搜索游标不移动。

重取只补全有证据的API字段，不抓取外部短链页面、不猜测或拼接回复，也不把X文章索引当正文。未知回复需要另行有界的同作者会话查询，当前实现不包含该流程。完整字段经既有正文解析后仍为未发布草稿，来源许可与发布审核不因重取解除。此决定对应可测试的恢复路径，不宣称已调用真实API恢复20条或增加公开内容。

## D-57：社区网页以固定来源、不可变作品和可信交互证据进入目录（2026-10-12）

首个社区网页路径仅接受署名完整、固定仓库版本的 prompts.chat CC0 条目。原创自包含 HTML 以 SHA-256 地址存于既有 R2 的 `examples/`，由只读内容 Worker 提供；不把一次性文件塞入会被下次部署替换的官网目录。固定 HTTPS 来源为 `api.prompix.dev`，Worker 强制 2 MB 上限、HTML 类型、无同源权限的脚本沙箱及禁止外部资源／连接的 CSP；第三方 Prompt、作品与截图仍不进入 Git。

运营者独立配置可信审核人。审核记录绑定精确原文、全部来源署名、作品和最终预览哈希；真实移动／桌面浏览器截图、键盘布局检查及逐项交互观察不可由截图模型判断替代。每日重新读取并核对托管作品与 JPEG，禁止重定向；已审 JPEG 跳过常规重编码。编辑元数据中的持久媒体覆盖恢复每次重新采集的附件，不能靠修改临时候选文件维持。缺证据或内容变化暂缓，新条目不发布，既有完整快照按原保留规则继续存在；下架仍优先。

作品审核不消耗视觉模型请求数，不授予新的来源许可，也不放宽视频连续动作或 X 来源关口。目录沿用现有 demoURL/imageURL 与九语言协议，原生无协议升级；合成往返测试不冒充真机或实际浏览器验收。本次决策记录代码机制，真实作品上线、交互审核和新增内容发布仍须以执行证据另记。

## D-58：内容质量暂缓只退出公开发现，不生成个人数据删除墓碑（2026-10-12）

明确的预览或内容质量问题可以由获授权操作者写入外部`quality-holds.json`，记录ID、完整原文／署名／媒体身份、审读理由、证据SHA-256、审读者和时间。创建时核对身份摘要与外部已审读目录中的准确原文、来源及媒体一致，之后按ID持续生效。现有内容锁串行保护维护与发布；严格结构、数量和文件大小校验失败时停止。该记录不是来源文字或自动模型输出授予的决定，候选及既有审批保留供修复，来源变化不会自动解禁。

正常目录组装在保留旧快照之后排除暂缓ID，防止保留规则复活已确认的质量问题。两个发布通道都执行，v1冻结快照只缩减，不因解除暂缓自动恢复增长；没有任何新的`removedIDs`。因此原生收藏及草稿沿用现有缺席快照行为，不触发明确下架删除。真正的许可、安全等下架仍使用独立墓碑流程。

暂缓与已有不可变pending或回滚目标冲突时停止激活并明确报错，保留原目标与指针；不静默重写、跳过暂缓或伪造空目录占位。质量修复后的重新收录要求明确审读解除暂缓，普通每日审核不能自行解除。本决定对应代码与合成测试，不宣称已经写入生产记录或更改当前目录。

## D-59：社区 Skill 固定作者和包版本，来源可用性覆盖保留与恢复（2026-10-13）

ClawHub 使用公开 API，并从三个作者／名称组合的白名单开始。请求固定作者，版本身份包含发布者ID及全部文件路径、大小和SHA-256，入口原始字节独立校验。完整文件清单变化会使编辑审批和决定缓存失效，不能仅凭相同说明文字沿用批准。注册表来源使用真实包页面与版本链接，原生九语言文案统一称来源页面；不改造为虚假的Git仓库，也不执行采集的文件。

每日及独立采集共用有界请求、六小时缓存和持久限流等待。来源状态在开始刷新时先失效，明确异常或未完成结果不保留旧许可。仅24小时内来源身份匹配的条目进入目录，旧内容保留之后过滤，冻结v1、pending恢复和新旧回滚均复核。此为来源发现可用性，不新增个人数据删除墓碑。待发布历史目标不再合格时停止并要求准备修正版；不会绕过检查直接恢复。此决定补充D-51：恢复未完成目标前可做不收费的注册表可用性刷新，仍不运行新付费审核或翻译。

真实研究的两项可采候选与一项暂缓只证明来源适配；正式发布仍需编辑、翻译与完整发布校验，不把候选数当线上数。具体流程及证据边界见[社区Skill采集](community-skills.md)。
