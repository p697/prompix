# 多语言内容翻译

初始语言为英文、简体中文、繁体中文、日文、韩文、西班牙文、巴西葡萄牙文、法文和德文（`en`、`zh-Hans`、`zh-Hant`、`ja`、`ko`、`es`、`pt-BR`、`fr`、`de`）。这是首轮产品覆盖选择，不代表经过统计的 AI 社区语言排名。中英文为必需，其他语言覆盖常见创作者与使用者社区；增加语言须同时更新协议、客户端选择器和翻译校验。

目录原始 title、summary、prompt、example、previewLabel 和 cover 文案始终保留。`localization` 只增加完整的语言版本，包括完整正文与使用说明，不用翻译标题代替翻译正文。sourceFingerprint 对上述原始字段的精确 JSON 字节做 SHA-256，编辑文案或来源正文改变后，旧记录不能沿用。原始来源、作者、许可、媒体地址、模型和可执行标识不翻译。sourceLanguage 只在脚本可辨识时标记；`und` 表示未知，不能当成英文。

缓存以语言与受保护文本 SHA-256 为键，相同文案跨条目复用，修改后的片段重新排队。代码块、行内代码、占位符、URL、模型名、模型参数、数字和 Skill frontmatter 在调用模型前替换为不透明标记，恢复时校验数量与内容。整体 JSON 正文只翻译自然语言字符串值，键、数组结构、数值和布尔值保持不变；模型参数、代码字符串和 quality=high 等机器枚举原样保留，quality 中的描述性句子仍要翻译。完整语言记录缺片段、丢失标记、目标文字系统不符、超过字段长度上限时不附加到目录。已有原创内置翻译与上一版校验过的线上译文都须匹配当前指纹并通过同样的语法检查才能复用；daily 重建条目时先按 ID 继承这些完整译文，避免缺失或局部缓存造成覆盖丢失。长文另有保守完整性检查：至少100个字母/汉字的文本，同为汉字的中文翻译不得缩为不足原文汉字量的50%，拉丁文字之间不得不足45%；跨文字系统最低15%，避免把正常英文到中文的压缩误判为删节。此类异常不附加到目录，后续用小批次补译。结构与长度检查不能证明所有语义与语言风格都正确；发布前仍应抽查长正文、技术术语和使用说明。

## 初次翻译与续跑

运行已审核、仓库外的完整目录；该命令只准备，不发布：

```sh
npx tsx ingest/translation-cli.ts /absolute/external/catalog.json --provider codex --max-requests 500
```

默认目录是 `~/.local/share/prompix/content/translations/`；`PROMPIX_TRANSLATION_DIR` 可指定另一个仓库外目录。每批完成立即原子保存 `cache.json` 和 `report.json`，结束后输出 `catalog.localized.json` 与 `coverage.json`。同一命令续跑只处理缺失或无效的片段。每批使用短数字 ID，缓存仍使用完整 SHA-256。已有原文仅在严格语言证据确认英文或简体中文时原样复用，记录 provider=original；短标题或混合语言继续请求翻译。预算计数也跨重启保留，除非显式指定 `--reset-budget`；失败或响应不明的调用占用请求名额。默认两进程、每批不超过 12,000 个原文字符／160 个片段、API 输出上限 24,000 tokens、CLI 每批输出文件上限 288 KB／十分钟超时、每批最多两次尝试。CLI 未提供可靠的单次输出 token 硬上限，预算由批大小、请求数、超时与账号额度控制。拒绝或语法失败的片段不会进入缓存，下一次运行只补缺；不可用模型、认证失败等永久错误立即停止全局工作。

本机 Codex CLI 0.153.3 的 ChatGPT 登录拒绝 `gpt-6.1-sol`，因此已实测可用的默认 CLI 模型为 `gpt-5.6-luna`、low 推理，`--model` 可显式调整，简体中文、日文和德文长文本实测保留含义与语法标记；先前 Terra 批次继续复用。实际模型和每片段来源保存在外部报告与缓存 provenance。CLI 使用现有 Codex 登录、只读临时目录和结构化输出，禁用 shell 与网页搜索工具，不读取仓库或公司凭据。此模式消耗账号的 Codex 使用额度，报告 `measuredUSD: null`，不能当作 API 的零美元账单。

若使用独立 Prompix OpenAI API Key，显式传 `--provider openai --max-usd 5`。仅从 Prompix 专用配置加载 `OPENAI_API_KEY`；不得复制其他公司项目的 Key。API 使用 GPT-6.1 Sol、low 推理、Standard 服务、`store: false` 和 JSON Schema。每次调用前按输入字节上界与输出上限预留费用，崩溃后保留该预留；实际 usage 按保守的未缓存价格估算，最终以控制台账单为准。当前 [GPT-6.1 Sol 官方价格](https://developers.openai.com/api/docs/models/gpt-6.1-sol) 为每百万 input $2、output $10，价格变化时需更新估算。CLI 模型与 API 模型有意独立，不能把两者的额度或费用混算。[结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) 同样指出模型仍可能产生语义错误。

命令与每日任务共用 `translations/run.lock`，避免覆盖缓存。异常中止留下锁时先检查 `owner.json` 的 PID 与活动进程，确认已停止后再恢复；不得删除正在运行的锁。写入故障会阻止新调用，并等所有活动请求结束后才释放锁。损坏或不可读的缓存明确阻止每日发布，避免把已有译文误当成空缓存删除。缓存、运行日志和第三方翻译均属于外部内容，不能提交 Git。

## 每日增量

通用 `npm run daily` 的 dry-run 明确禁止调用模型，即使已加载付费 provider 配置，仍只读取验证过的缓存。发布任务只有在 `~/.config/prompix/translation.env` 显式启用并由运行器加载以下变量才允许补译：

```dotenv
PROMPIX_TRANSLATION_PROVIDER=codex
PROMPIX_TRANSLATION_MODEL=gpt-5.6-luna
PROMPIX_TRANSLATION_MAX_REQUESTS=36
PROMPIX_TRANSLATION_MAX_USD=2
```

Codex路径受请求数、批大小、超时和账号额度控制，`PROMPIX_TRANSLATION_MAX_USD=2` 不构成Codex的美元费用上限，实测费用保持null；美元预留只用于直接OpenAI API路径。此变更不修改现有翻译重试策略：每批最多两次尝试，均提前预约且计入当天累计请求。

每次仅处理已经通过当前来源指纹编辑审核的内容。每日默认最多36次请求，预算写入 `translations/daily-budgets/YYYY-MM-DD.json`，按 UTC 天计数，手动重跑同一天不会重置。批次按语言轮流执行，首语言逐日轮换，避免长条目占满预算而令后面的语言长期缺译。该默认值配合元数据／视觉各四次审核批次，为九语言留出更多补译名额，但不保证36次可以处理任意十二条内容；大Skill、长正文与失败重试可能占用多批，pendingRecords明确报告待补数量。已有显式 `PROMPIX_TRANSLATION_MAX_REQUESTS=12` 仍覆盖新默认，升级运行器不会自动改写环境文件。若初次完整翻译正在占锁，每日任务跳过模型调用，仍可复用原子保存的已验证缓存；翻译故障也不会把无效翻译发布。`status.json` 的 translations 逐语言报告完整条目 coverage 与 pendingRecords，而非只统计某些标题已翻译的数量。缺少完整语言记录的条目继续保留原文与已有完整译文，由客户端明确回退；待后续预算补齐，不伪装成该语言已完成。

单次补译可设置 `PROMPIX_TRANSLATION_LOCALES=zh-Hans,en`，只排队这些语言，仍轮流处理选中的语言。仅接受互不重复的完整语言代码；空值、未知代码或重复值会在调用模型前失败。未设置时继续九语逐日轮换。筛选不会建立新账本、重置已消耗请求或删除其他语言缓存；同一天换语言续跑仍扣同一个 UTC 日总预算。临时优先补中英文时只给当前进程传入，勿改写定时器的九语默认。生产增量补译应使用此每日路径，不要用独立 CLI 的另一个账本或 `--reset-budget` 绕过每日额度。

每日处理也会读取外部已完成的 `translations/catalog.localized.json`，仅按 ID 继承源指纹一致且通过字段校验的语言记录；在部分缓存无法独立重组完整正文时，仍能使用完整校验成果。取得翻译锁后重新读取缓存、审查清单与此目录，避免手工任务刚完成时使用过期快照。损坏的已完成目录同样阻止处理，缺失则允许只读缓存与线上已有译文。升级定时运行器后才能使用新的模块和配置加载。单独翻译命令不会修改定时器、最新线上清单或 R2。译文应先随 staging 与目录检查复核，然后由现有发布流程激活。

## 验证

`npx tsx --test ingest/translation.test.ts` 覆盖不透明标记、Skill frontmatter、JSON 键与参数、源文修改失效、完整字段覆盖、已有离线译文校验、重跑零调用、失败重试、永久错误立即停止、请求与费用预留、通用 daily 不调用模型、锁冲突时读取缓存、缓存损坏阻止发布及写入失败等待活动请求结束。

人工语义审查发现的错误保存在外部 `translations/semantic-rejections.json`，每条包含 `locale`、`segmentID`、被拒译文的 `translationSHA256` 与 `reason`；可同时提供原文 `sourceSHA256` 和恢复后译文 `renderedTranslationSHA256`，让修改保护规则后的缓存和继承值仍不能复活同一个错误。共享受保护片段会保留所有原文上下文并逐一检查。只失效这个精确输出，修正后的同一片段仍可缓存。手工 CLI 和 daily 都读取此清单；缓存、模型返回值和上一版目录继承值均不能复活被拒译文。清单损坏会停止处理，不能静默忽略。新增审查记录后，运行相同 CLI 即只补缺失/失效片段。

精确的最小语义修正可通过 `applyReviewedCorrections` 导入；调用方必须先持有相同翻译锁。外部修正文件绑定条目、语言、字段、原文、旧译文和片段哈希，恢复后的文本仍须保留全部不透明值。已更新的缓存不会被覆盖。修正片段记录 `provider=agent-reviewed` 与实际审查模型，不能继续声称是原模型未经修改的输出；外部审查文件保留理由和修改前后内容。

忠实翻译必须保留源文指定的输入/输出语言，例如“用中文回答”不能改成当前界面语言。图像/视频中明确要求绘制的引号文字、标题、标语、按钮标签保留字节；周围说明正常翻译。数值仍使用不透明 token，同时向模型提供数值语法提示，以避免“1 vueltas/1 vezes”等单复数错误。完整性与语言检查只能发现部分错误；发布前仍需抽查长段落、重复镜头要求、专业术语、图中文字和条件式语言指令。

语言要求校验不再把“语法文档／語法文件”中的跨词“法文”误判为法语要求，避免阻止技术说明的正确译文。“法文／法语／法語”和“法文文档”仍须保留语言含义；只有语法文档描述的译文也不能冒充已保留 French 指令。此修正不自动修改缓存或发布内容。

方括号中的真正变量与填写提示保持原样；普通章节标题、完整叙述段落和描述性数组正常翻译并保留括号结构，不能把整段中文伪装成占位符。明确的示例输入（如土耳其语首句）也按原字节保留，避免把语言练习的输入替换成译文。同一文本中的重复绘制文案统一保护，避免整句与内层变量重叠导致误判。
