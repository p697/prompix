# Prompt 的复制、分享与工具交接

更新：2026-10-13。适用文本、图片、视频、网页四类 Prompt。能力以实际验证为准，工具集合可扩展。

## 1. 首版底线

每条内容可复制完整原文、简单编辑后复制，并通过系统分享发送文本和来源链接。收藏文本离线也能复制。App 内不执行 Prompt、不自动发送消息、不代用户生成内容。

详情说明所需输入、模型和目标工具。网页／代码动效可能需要电脑或特定工具，不能仅凭预览是视频就认定它适合视频生成器，也不能按“图片／视频”一刀切禁用某个工具。

## 2. 按条目提供能力

| 能力 | 实现与承诺 |
|---|---|
| 复制 | 用户操作后复制原文或本地编辑后的文本，明确反馈 |
| 系统分享 | 分享 Prompt 与来源链接；目标应用是否接收、如何接收由该应用决定 |
| 打开工具 | 使用经过验证的 URL，在适用工具或浏览器中打开；不能等同于预填成功 |
| 预填 | 开发版仅启用有官方说明的入口，分别记录浏览器预填与原生 App 验证；最终交付仍需实际目标工具验收 |

0.4.5 对网页 Prompt 增加 Lovable 和 Claude Code 的官方预填入口；普通聊天及未明确支持预填的工具仍使用复制加打开。需要参考图片、视频或文件时，说明用户要在目标工具中添加，不承诺一次传入全部素材。超长文本不强塞 URL。

## 3. 配置

条目的 `toolURL` 随静态目录发布；客户端使用系统 HTTPS 链接打开，默认始终提供复制／分享。原生 `PromptDestination` 只对固定的官方入口构造预填链接，其他来源 URL 原样打开。

旧版记录过 ChatGPT、Grok、Gemini、Claude 的链接候选，可在实现阶段重新核实，但不把历史通用链接声明视为预填证据。本版不要求地区排序、不限于这四个工具，也不做 Android 交接实现。

## 4. 真机验证

对每个启用的工具记录系统版本、工具版本、测试日期与结果：

- 是否安装工具；打开后是原生工具还是浏览器；网络／登录异常如何显示。
- 文本是否预填、是否完整、有无意外发送；记录实际环境，不把 URL 构造或浏览器成功当作原生 App 实测。
- 中文、emoji、换行、长文本是否保真，用户编辑内容是否按预期复制。
- 系统分享是否可完成；取消后不误报成功，不假设系统一定返回完成状态。
- 参考素材是否仍须手动添加；网页示例打开与 Prompt 发送到工具是不同操作。

模拟器验证应用内流程，真机验证外部工具行为。复制成功、链接打开和生成完成是三个不同结果。

## 5. 观测

验收时人工记录条目 ID、内容类型、复制／分享／工具打开动作及可观察结果。App 本身不上传这些操作事件；工具打开不当作生成成功，也不采集用户填写的 Prompt 内容或个人信息。Android 在后续原生开发时另定交接细节。

## 2026-10-13：0.4.0 原生使用面板

本节取代第 3 节“没有独立工具注册表”的旧状态。`PromptDestination` 根据模态与条目推荐 URL 提供工具选择，常用工具按稳定身份记忆。视频只展示条目提供的工具，避免推荐不支持对应任务的通用聊天工具。HTTPS 链接有凭据或非标准端口时不进入快捷交接。

详情的「使用」打开当前语言的本地草稿；编辑器打开其当前文字，保存失败也不会交接旧稿。面板提供全文预览、复制、系统分享和「复制并打开工具」；先完整写入剪贴板，再调用系统打开链接。打开失败保持内容并提示手动粘贴。用户仍需在目标工具确认发送、模型及参考素材；不把未知的 URL 参数当作预填接口。

官方 GitHub Skill 可以复制或分享 `npx skills add` 命令，固定审核时的 commit、目录与 Skill 名称。只为经过路径校验的官方目录生成命令，无自动确认、全局安装或自动执行。依据为 [Skills CLI 文档](https://github.com/vercel-labs/skills#source-formats)。社区 Skill 继续提供完整来源链接，不编造通用安装命令。原始 SKILL.md 仍可在详情复制。

Claude 官方目前记录了 [Code 页深链](https://support.claude.com/en/articles/14898120-open-the-claude-mobile-app-with-a-link)，需要 Claude Code 权限，不等同于普通聊天预填。因此这版采用明确的复制加打开，不向所有用户显示未经真机验证的预填承诺。


0.4.1 补齐已识别模型的官方入口：Nano Banana→Gemini、GPT Image→ChatGPT、Midjourney→官网、Seedance→Dreamina、Veo→Flow、Runway→应用站。仅在内容未自带工具 URL 时采用，未知视频模型不猜链接；仍由用户在目标工具粘贴、选择模型与提交。

0.4.4（15）新增 Expo／Supabase 官方 Skill 的固定 commit 安装命令，限定其公开包根目录。详情显示完整文件清单、原始来源与作者；复制安装命令交给桌面编程助手，不在手机执行安装。

## 0.4.5（16）：手机工具入口

网页 Prompt 的使用面板增加 Lovable、Claude Code，普通 Claude 聊天仍是独立选项。Lovable 使用官方 fragment prompt，Claude Code 使用官方新会话 q 参数；不设置自动发送、目标仓库或分支。用户在目标工具确认提交，参考图片和文件仍需自行添加。依据：[Lovable Build with URL](https://docs.lovable.dev/integrations/build-with-url)、[Claude 移动链接](https://support.claude.com/en/articles/14898120-open-the-claude-mobile-app-with-a-link)。

固定版本官方 Skill 额外提供「在 Claude Code 中准备安装」，将同一安装命令带入输入框，明确需要 Code 权限和用户自己的项目；保留桌面安装命令复制与分享。社区或无法验证固定安装目录的 Skill 不生成这一入口。

链接按 UTF-8 百分号编码并以编码后的 8192 字节作为客户端保守上界；超长文本不截断，改用原入口并复制完整正文。空白文本不能打开。每次打开前保留全文剪贴板，系统拒绝打开时仍可手动粘贴。此上界不冒充服务商公布的最大长度。新增界面文案全部覆盖九种语言。

实际边界：Lovable 未登录浏览器已看到完整中文、换行及分隔符文本停在输入框，没有发送；Claude Code 未登录页面保留了带 q 的登录回跳地址，未登录、未启动代码任务，不宣称已验证其原生 App 或账号内执行。模拟器已通过网页选择、系统打开及返回、Skill Code 入口和复制备用两条流程；正文 689 字节与安装命令 158 字节分别逐字节核对一致，原有草稿哈希不变。161 项原生模型测试与 240 键九语检查通过。证据位于开发机 SSD 的 `Prompix-Codex/Evidence/mobile-handoff/`；用户手机未安装。

## 0.4.6（17）：先填写自己的需求

详情的「使用 Prompt」和完整编辑器在发现明确占位符时提供「填写变量」。原生表单显示原变量名、所在原句和完整结果预览；支持多行、重复字段和带默认值的 `${name:default}`，也识别保守范围内的双花括号、单标识符花括号和方括号。取消不写草稿，留空保留原始标记；应用后更新当前语言的本地草稿，复制、分享与工具打开使用同一份完整结果。保存失败保留内存正文，显示复制备用和重试入口。

表单仅在设备本地工作。Skill、完整 JSON／HTML、代码围栏、行内代码、Markdown 链接、明显章节标签不作为输入；超过 50,000 个 UTF-16 单元或 32 个字段时保留完整编辑器。用户填入的新标记按普通文字处理，不递归替换。识别是可选辅助，不承诺理解任意模板语法，也不补写来源指令。

当前构建在 455 条真实缓存目录通过填写、取消、当前语言草稿保存、复制和重启编辑恢复流程；515 字节剪贴板与预期逐字节相同，既有草稿保留。172 项原生模型测试、245 键九语检查通过。证据在开发机 SSD 的 `Prompix-Codex/Evidence/prompt-inputs/current-build.xcresult`。此前测试启动器复用旧安装版本的问题已通过实际二进制哈希核对与显式模拟器安装排除；早期失败记录不计入通过项。最大字号和最终整体质量检查仍继续。
