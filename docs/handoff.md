# Prompt 的复制、分享与工具交接

更新：2026-10-11。适用文本、图片、视频、网页四类 Prompt。能力以实际验证为准，工具集合可扩展。

## 1. 首版底线

每条内容可复制完整原文、简单编辑后复制，并通过系统分享发送文本和来源链接。收藏文本离线也能复制。App 内不执行 Prompt、不自动发送消息、不代用户生成内容。

详情说明所需输入、模型和目标工具。网页／代码动效可能需要电脑或特定工具，不能仅凭预览是视频就认定它适合视频生成器，也不能按“图片／视频”一刀切禁用某个工具。

## 2. 按条目提供能力

| 能力 | 实现与承诺 |
|---|---|
| 复制 | 用户操作后复制原文或本地编辑后的文本，明确反馈 |
| 系统分享 | 分享 Prompt 与来源链接；目标应用是否接收、如何接收由该应用决定 |
| 打开工具 | 使用经过验证的 URL，在适用工具或浏览器中打开；不能等同于预填成功 |
| 预填 | 仅对已通过真机验证的工具／链接启用，不是首版上线前提 |

当前客户端分别提供复制按钮与“复制后打开工具，粘贴使用”的外链，不宣称一键预填。需要参考图片、视频或文件时，说明用户要在目标工具中添加，不承诺一次传入全部素材。超长文本不强塞 URL。

## 3. 配置

条目的 `toolURL` 随静态目录发布；客户端使用系统 HTTPS 链接打开，默认始终提供复制／分享。当前没有独立工具注册表或自动预填策略。

旧版记录过 ChatGPT、Grok、Gemini、Claude 的链接候选，可在实现阶段重新核实，但不把历史通用链接声明视为预填证据。本版不要求地区排序、不限于这四个工具，也不做 Android 交接实现。

## 4. 真机验证

对每个启用的工具记录系统版本、工具版本、测试日期与结果：

- 是否安装工具；打开后是原生工具还是浏览器；网络／登录异常如何显示。
- 文本是否预填、是否完整、有无意外发送；只有实测通过才能显示预填文案。
- 中文、emoji、换行、长文本是否保真，用户编辑内容是否按预期复制。
- 系统分享是否可完成；取消后不误报成功，不假设系统一定返回完成状态。
- 参考素材是否仍须手动添加；网页示例打开与 Prompt 发送到工具是不同操作。

模拟器验证应用内流程，真机验证外部工具行为。复制成功、链接打开和生成完成是三个不同结果。

## 5. 观测

验收时人工记录条目 ID、内容类型、复制／分享／工具打开动作及可观察结果。App 本身不上传这些操作事件；工具打开不当作生成成功，也不采集用户填写的 Prompt 内容或个人信息。Android 在后续原生开发时另定交接细节。
